# 经验总结

---

## 1. 关键收获

### 1.1 SDD 方法论的价值

**1. 规范先行，代码在后**

通过 SDD 七步工作流，我们在编码前花时间编写了详细的规范和计划，这为后续的开发节省了大量时间。

**对比**：
- **传统方式**：边写边改，返工率高
- **SDD 方式**：30 分钟写规范 = 节省 3 小时返工

---

**2. Clarify 环节不可跳过**

Clarify 环节暴露了 15 个关键问题，如果这些到编码阶段才发现，修改成本将提升 10 倍以上。

---

### 1.2 技术选型经验

**后端技术栈**：
- MyBatis-Plus：灵活性高，适合复杂查询
- Redis：高性能内存数据库
- Spring Security + JWT：业界标准

**前端技术栈**：
- React Query + Zustand：前后端状态分离
- Tailwind CSS：Utility-first，开发效率高
- Vite：启动快，热更新快

---

### 1.3 代码质量经验

**代码规范**：
- 所有公共方法必须有 Javadoc
- 所有 Service 方法必须有单元测试（覆盖率 ≥ 80%）
- 所有 Controller 方法必须有集成测试
- RESTful API 风格统一
- 数据库设计遵循下划线命名法

**测试金字塔**：
```
        /\
       /E2E\        (10%)
      /------\
     / 集成测试 \    (20%)
    /----------\
   /  单元测试   \  (70%)
  /--------------\
```

**单元测试覆盖**：82.5%

---

### 1.4 数据库设计经验

**ER 图重要性**：
- 明确实体关系（1:1, 1:N, N:M）
- 明确外键关系
- 明确索引设计

**最佳实践**：
- 所有表有 created_at/updated_at
- 逻辑删除（deleted 字段）
- 合理的索引设计
- 字符集使用 utf8mb4

---

### 1.5 缓存策略经验

**缓存层级**：

| 缓存层级 | 缓存内容 | TTL |
|---------|---------|-----|
| 应用缓存 | 客户列表、商机列表 | 30 分钟 |
| 应用缓存 | 报表数据、统计数据 | 1 小时 |
| 应用缓存 | 用户信息 | 2 小时 |

**缓存更新策略**：先更新数据库，再删除缓存

## 3. 实战要点

### 3.1 后端实战要点

**统一响应格式**：

```java
public class Result<T> {
    private Integer code;
    private String message;
    private T data;
    private Long timestamp;

    public static <T> Result<T> success(T data) {
        return new Result<>(200, "success", data, System.currentTimeMillis());
    }
}
```

**JWT 认证**：

```java
public String generateToken(String username, String role) {
    return Jwts.builder()
        .setSubject(username)
        .claim("role", role)
        .setExpiration(new Date(System.currentTimeMillis() + EXPIRATION_TIME))
        .signWith(SignatureAlgorithm.HS256, SECRET_KEY)
        .compact();
}
```

**Redis 缓存**：

```java
public CustomerResponse getCustomerById(Long id) {
    String key = "crm:customer:" + id;
    Customer cached = (Customer) redisTemplate.opsForValue().get(key);
    if (cached != null) {
        return convertToResponse(cached);
    }
    Customer customer = customerRepository.findById(id);
    if (customer == null) {
        return null;
    }
    redisTemplate.opsForValue().set(key, customer, 30, TimeUnit.MINUTES);
    return convertToResponse(customer);
}
```

## 4. 常见问题与解决方案

### 4.1 后端常见问题

**问题 1：N+1 查询问题**

**解决方案**：
```java
// 使用 MyBatis-Plus 的 selectBatchIds
List<Customer> customers = customerRepository.selectBatchIds(customerIds);
```

---

**问题 2：缓存穿透**

**解决方案**：
```java
// 缓存空值（TTL 5 分钟）
if (customer == null) {
    redisTemplate.opsForValue().set(key, "null", 5, TimeUnit.MINUTES);
    return null;
}
```

---

### 4.2 前端常见问题

**问题 1：TypeScript 类型错误**

**解决方案**：
- 定义详细的 TypeScript 类型
- 使用 interface 替代 type
- 使用 strict 模式

---

**问题 2：状态管理混乱**

**解决方案**：
- React Query 处理服务端状态
- Zustand 处理客户端状态
- 避免直接修改 React Query 缓存

# 功能规格：权限体系加固（Security Hardening）模块

**功能分支**: `063-security-hardening`

**创建日期**: 2026-08-25

**状态**: 草稿

**输入**: 系统安全审计（4 维并行审计）发现的高/中风险项。本模块按 SDD 流程修复授权模型覆盖不均衡问题：**行级数据权限只做了客户（CustomerService）一处**，其余核心业务实体（线索/联系人/跟进/评论/共享/导出）对任意登录用户开放。目标：将角色级 + 行级数据权限覆盖到全部核心实体，并加固异常处理与导出安全。

## 用户场景与测试（必填）

### 用户故事 1 - 线索/联系人/跟进/评论行级数据权限（优先级：P0）

非 ADMIN 用户只能查看/修改/删除**自己负责（owner）或已共享**的线索、联系人、跟进与评论；列表按数据范围过滤；写操作校验归属。

**优先级理由**: 当前任意低权限账号可读/改/删/导出全部线索与联系人 PII，是最严重的越权面（审计 S3）。

**独立测试**: SALES 用户看不到他人线索；他人线索更新被拒。

**验收场景**:

1. **Given** 两条线索（owner 分别为 A、B 用户），**When** A 查看线索列表，**Then** 仅见 owner=A 的线索。
2. **Given** A 尝试修改 owner=B 的线索，**When** 提交，**Then** 403 拒绝。
3. **Given** 客户共享给 A，**When** A 查看该客户联系人，**Then** 可见（共享继承）。

---

### 用户故事 2 - 数据导出安全（优先级：P0）

导出接口按数据范围过滤 + 敏感字段脱敏；SALES 只能导出自己可见的数据，手机/邮箱脱敏（非 ADMIN）。

**优先级理由**: 当前 SALES 可导出全库客户手机/邮箱明文（审计 S4）。

**独立测试**: SALES 导出仅含本人数据；导出文件中手机号已脱敏。

**验收场景**:

1. **Given** SALES 用户触发客户导出，**When** 下载，**Then** 文件仅含该用户可见客户。
2. **Given** 导出文件含手机号字段，**When** 查看，**Then** 非 ADMIN 导出中手机号已脱敏（如 138****0000）。
3. **Given** ADMIN 导出，**When** 查看，**Then** 明文完整。

---

### 用户故事 3 - 异常响应加固（优先级：P1）

坏请求/资源不存在/唯一键冲突返回正确的 400/404/409，不再落 500；内部异常不泄露细节。

**优先级理由**: 审计 B5——坏 JSON、路径参数类型错、唯一键冲突当前返回 500，影响排障与客户端处理。

**独立测试**: 提交坏 JSON → 400；改不存在资源 → 404；重复唯一键 → 409。

**验收场景**:

1. **Given** 请求体不是合法 JSON，**When** 提交，**Then** 返回 400（当前 500）。
2. **Given** 路径参数类型错误（如 id=abc），**When** 请求，**Then** 返回 400。
3. **Given** 插入重复唯一键（如重复用户名），**When** 提交，**Then** 返回 409。

### 边界情况

- ADMIN 恒全量可见/可写（豁免行级过滤）。
- 共享继承：客户共享给用户 → 该客户的线索/联系人/跟进/评论对共享用户可见。
- 数据范围过滤对 detail/update/delete 与列表一致生效。
- 导出过滤与脱敏对 ADMIN 豁免。

## 需求（必填）

### 功能需求

#### 行级数据权限

- **FR-H01**: 线索列表/详情/更新/删除必须按 owner + 共享过滤（非 ADMIN）。
- **FR-H02**: 联系人列表/详情/更新/删除必须按所属客户可见性过滤。
- **FR-H03**: 跟进/评论必须按关联实体可见性过滤。
- **FR-H04**: 写操作（更新/删除/分配/转换）必须校验归属（403 拒绝越权）。
- **FR-H05**: ADMIN 恒全量豁免。

#### 导出安全

- **FR-H06**: 导出必须按数据范围过滤（非 ADMIN 仅导出可见数据）。
- **FR-H07**: 非 ADMIN 导出手机/邮箱必须脱敏；ADMIN 明文。

#### 异常加固

- **FR-H08**: 坏 JSON/参数类型错/缺参数 → 400。
- **FR-H09**: 资源不存在路径 → 404；唯一键冲突 → 409。
- **FR-H10**: 内部异常不泄露内部细节（统一 500）。

#### 权限与约束

- **FR-H11**: 控制器角色注解与现有权限体系（@PreAuthorize/@RequirePermission）一致补齐。

### 关键实体（涉及数据）

- 复用 DataPermissionService（012 数据权限）、CustomerShare（共享）、MaskingUtil（脱敏）。
- 无新增表。

## 成功标准（必填）

### 可度量结果

- **SC-H01**: 线索/联系人/跟进/评论越权测试全绿（新增 ≥8 个越权场景测试）。
- **SC-H02**: 导出过滤与脱敏测试通过（SALES 可见集 + 脱敏断言）。
- **SC-H03**: 400/404/409 异常测试通过（≥4 场景）。
- **SC-H04**: `mvn verify` 全绿（含既有 135+ 测试无回归）；前端 typecheck/lint/build 通过。

## 假设

- 数据范围过滤规则与 CustomerService 现有一致（owner 可见集 + 共享）。
- 线索 owner 与客户 owner 独立管理（线索无客户时按线索 owner 过滤）。
- v1 不改数据模型（无迁移）。

## 依赖

- 012 数据权限（DataPermissionService）、共享（CustomerShare）、脱敏（MaskingUtil）。

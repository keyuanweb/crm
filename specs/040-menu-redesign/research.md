# Research: 菜单分类重设计模块

**Branch**: `040-menu-redesign` | **Date**: 2026-08-24

## 1. 现有菜单问题

**Decision**: 现有分组（客户/销售/交易/基础资料/营销与服务/数据分析/系统管理）存在：基础资料组仅 2 项（任务/产品）过薄；营销与服务混组（营销活动/邮件/表单/工单/知识库语义跨度大）；数据分析混入导出中心（工具类）与流失预警（客户域）；系统管理 13 项过载；公告管理与我的审批为全员功能却仅 ADMIN 可见。

**Rationale**: 分组服务于"找得到"——语义聚合 + 数量均衡；权限归位保证非管理员可用应有功能。

## 2. 新分组方案

**Decision**: 9 个菜单入口（首页置顶 + 8 分组）：

| 分组 | 项 |
|---|---|
| 首页（置顶） | 统计仪表盘 |
| 客户管理 | 线索、客户、联系人、查重合并、流失预警 |
| 销售管理 | 商机、销售机会、报价单、外勤拜访、产品 |
| 交易管理 | 合同、订单、发票 |
| 营销中心 | 营销活动、邮件营销、在线表单 |
| 服务协作 | 客户服务（工单）、知识库、公告管理、我的审批 |
| 工作台 | 任务、智能建议、数据大屏 |
| 数据分析 | 自定义报表、团队排行、导出中心 |
| 系统管理（ADMIN） | 用户、角色权限、标签与细分、部门、工作流、审批流配置、自定义字段、合同模板、SLA 策略、审计日志、回收站 |

**Rationale**: 业务域聚合（线索-客户-联系人-合并-预警 = 客户全生命周期）；营销中心独立（活动/邮件/表单 = 获客手段）；服务协作聚合（工单/知识库/公告/审批 = 内部协作）；工作台聚合（任务/建议/大屏 = 个人日常）；数据分析精简（报表/排行/导出）；系统管理仅配置类。

**Alternatives considered**: 维持现状（仅微调）——不解决过载/错位问题；按模块编号分组——违背业务语义。采用业务域分组。

## 3. 权限映射同步

**Decision**: `menuKeyOf` 的 path→key 映射表随菜单移动同步更新（如 /customers/at-risk 归 customers、/approvals 归 workflows 等沿用既有 key），028 角色过滤逻辑不变；移动端拍平逻辑不变。

**Rationale**: 菜单可见性由 user.menus 驱动，移动路由数组不影响过滤 key 语义。

## 1 由来

P1 #16 原文：「★ **前端 i18n 的串级残留** | — | 页级已闭合，**11 个文件仍有中文字面量**（最重 `LoginPage.tsx` 13 处），建议作日常清扫」。

它是一条**从未被任何脚本支撑过的人工读数**（取于 2026-09-14），而仓里**没有任何门禁看着「源码里的硬编码中文」**：
`frontend/scripts/` 下 6 个脚本零命中（`check-i18n.mjs` 只管**资源键**、不管源码字面量），`eslint.config.js` 无 i18n 插件。
⇒ 这件事**既没有可复算的基线，也没有防回潮的护栏**。

### 1.1 前提订正：「11 个文件」复现不出来（**这是本项最重要的输入**）

用仓库里**既有**的 AST 扫描器 `frontend/.i18n-keys/find-hardcoded-zh.mjs` 实测：

| 项 | 报告写 | 实测（2026-09-16，本项立项前亲手复算） |
|---|---|---|
| 文件数 / 处数 | **11** / 未给 | **15** / **300** |
| 同一脚本在 `8a7c438`（2026-09-14 最后一次提交）的树上跑 | — | **逐文件逐数完全相同**（零漂移）⇒「11」来自**另一套口径**，不是漂移造成的 |
| `LoginPage.tsx` | **13** 处 | **13** 处，与报告一致；自 2026-08-25 起**一字未增**（082 只往该文件加注释） |
| 「11」唯一算得准的构造 | — | 15 − 4 个大户（`usageMap.ts` 142 / `menuManifest.ts` 67 / `App.tsx` 57 / `breadcrumbTrail.ts` 2）= **11 文件 / 32 处** |

⚠️ **那条减法只能报告为「推断」，不能报告为「已验证」**：文档里**没有留下**生成「11」的命令或输出。
另外两个自然口径的实际值也都不是 11：**用户可见 UI 文本（含全角标点）= 13 个文件**、**非注释中文 = 37 个文件**（`research.md` §1 给全）。

### 1.2 两条决定形状的实测事实

**① 口径只能是 AST，不能是正则。** 本仓注释按约定就是中文：`src/` 下含中文的行 **2452** 行、注释命中 **6032** 处。
既有脚本用 TypeScript 编译器 API ⇒ **注释天然不在 AST 里**，只数 `StringLiteral` / `NoSubstitutionTemplateLiteral` / `JsxText`。
`typescript ^5.3.3` 在 devDependencies ✓。**任何正则式扫描都会把 6032 处注释算成违规。**

**② 那个脚本本身没进版本库，也没接 CI。** `frontend/.i18n-keys/` 整目录被 `frontend/.gitignore` 忽略
（注释理由是「防止并行会话的 `git add -A` 把中间产物提交进来」），`git ls-files` 返回空。
⇒ **今天任何一个别的人/机器都算不出「300/15」** —— 这是本次调查对**可复现性**威胁最大的一条，
也是本项必须**把它提升为版本库内的门禁**、而不是另写一套的原因。

### 1.3 「界面不变」为什么是可保证的

`frontend/src/test/setup.ts:95-123` 的 `vi.mock('react-i18next')` 让 **`t(key)` 返回 key 本身**（且缺键直接抛错）；
而 **e2e 用真 i18n 渲染中文**（`frontend/e2e/` 下 **444** 处中文断言）。
⇒ 只要新键的 **zh-CN 值与原字面量逐字相同**，**e2e 与视觉效果不变**；代价是**单测里断言这些中文的用例必须改成断言键名**。
**实测这份代价只有 3 个文件 / 5 行**（见 §3.6）。

## 2 用户故事

### US1 能清的清掉，且「清掉」不靠人记得（P1）

**角色**：下一个在这个仓里写前端的人；**诉求**：想知道**用户看得见的中文到底还有没有硬编码的**，
并且**改了之后不会有人再悄悄加回来**。

**为什么**：今天答案是「不知道」——读数悬空、无门禁、无台账。
**验收**：① 窄口径的 **34 处 / 12 文件**清零；② 新门禁 `zh:check` 落地，**此后任何一处回潮都转红**；
③ 清零这件事由门禁的**第三条分支**强制（文件清了、台账条目没摘 ⇒ 红），**不靠人记得改台账**。

### US2 「不该动的那些」第一次被写成可执行判据（P1）

**角色**：下一个看到 `usageMap.ts` 里 142 处中文、想「顺手也清了吧」的人；
**诉求**：一眼知道**为什么这 266 处不该动、动了会坏什么**。

**为什么**：这三类（演示数据 / 生成物 / 降级真源）**从来没有任何地方说过话**，
而它们占了 300 里的 266 —— 没有台账的门禁只能靠「白名单太长了所以不写」来回避，那等于没有门禁。
**验收**：**4 条冻结台账**，每条 `reason` 是散文、写明**类别**与**是否含欠账**；
其中 `App.tsx` 那条**点名 2 处真欠账**（不许洗成「不是缺陷」）。

### US3 两本账不再互相绊倒（P2）

**角色**：下一个改 `check-ui.mjs` 的人；**诉求**：R6 的白名单里不要再躺着两条「属 i18n 清扫批次」的欠账。

**为什么**：`R6_ALLOWED` 的 2 条 `reason` 原文就写着「属 i18n 清扫批次」，
而**这批就是那个批次**；不摘的话 R6 的双向校验会因「count 多了」当场转红（机器强制，不是可选项）。
**验收**：R6 由 **8 条 / count 合计 10** 变为 **6 条 / 8**；块头注释里那两个聚合数**再订正一次**
（**原文逐字保留 + 带日期 ⚠️ + 更新两条 `awk` 复算命令**）；⚠️ **写明「摘的是两条白名单，规则本身不动」**。

### US4 登记表与文档里的数当天是对的（P2）

**角色**：按 `PROJECT_FEATURES.md` 做决策的人。
**验收**：P1 #16 的旧读数**原文逐字保留**并附带日期 ⚠️ 块（写明实测 15/300 与本项处置）；
`PROJECT_FEATURES.md` §一 的 i18n 资源行与 Spec 模块行改为实测值；**旧值仍可 grep 到**（订正不静默）。

## 3 功能需求

### 3.1 门禁（新建）

- **FR-001** 新增 `frontend/scripts/check-zh.mjs`（`pnpm zh:check`，**新关注点一脚本**，不与既有四个脚本合并）：
  - **口径逐字复用**既有扫描器：节点 `ts.isStringLiteral` + `ts.isNoSubstitutionTemplateLiteral` + `ts.isJsxText`（`trim()` 非空）；
    CJK 正则 `/[一-鿿]/`（**U+4E00–U+9FFF**）；跳过 `import` 声明；排除 `src/i18n/**` 与 `*.test.*`。
    **文件头必须写明口径来源与「为什么不像 `check-ui.mjs` 那样用正则」**（否则下一个人会把它"简化"成正则）。
  - **台账** `ZH_ALLOWED`（`{ file, count, reason }`），`reason` **必填散文**且写明**类别**与**是否含欠账**。
  - **三分支双向校验**：① 未登记命中 ⇒ 红；② 某条 `count` **多了** ⇒ 红；③ 某条 `count` **少了（含已归零）** ⇒ 红。
  - **反假绿**：`MIN_CANDIDATES.ZH`（**被执行的下限**）+ `CANDIDATE_READINGS.ZH`（历史实测值，**只用于区分「扫描器坏了」与「规则该退役」**）。
  - **失败信息**：按 `【kind】N 处` 分组 + `第 N 行：<text>` + `修复：<fix>`。
  - **`--list`**：打印逐文件逐行清单（= 本项工作单，也是下一批的入口）。
- **FR-002** **口径边界自证（信息性，不影响退出码）**：脚本除主口径外跑一遍**宽口径次级扫描**
  （同一批 AST 节点，正则放宽到含全角标点区间，并额外收 `TemplateExpression`），
  打印一行「本脚本判 N；**口径外另有 M 处**」。⚠️ **这一行不进 `problems`、不改退出码**，
  **必须在脚本注释与留痕里写明它不判** —— 理由：**任何扫描器对自己的盲区自证不了，所以边界必须被印出来，不能靠读者假设**。

  （与既有 8 步并列；⚠️ 按 `083` 的既有订正，本仓**无远端、CI 一次都不会触发**，门禁口径**以本地命令为准**）。

## 4 非目标（明确不做，且各有理由）

1. **不清零 `App.tsx` 那 53 处路由 `name:`** —— 它们是 `check-i18n.mjs` 路由枚举正则的输入，**界面渲染根本不走它们**；改它们要动路由表结构，收益为零。
2. **不清零 `App.tsx` 的 2 处真欠账**（`渠道 ROI` / `工作流日志`）—— 要改路由表（加 `i18nKey`）与 `:542` 的取词，属**结构调整**；
   已在台账理由里**点名**，留给下一批（**不许当成「不是缺陷」**）。
3. **不清零 `usageMap.ts`(142) / `menuManifest.ts`(67) / `breadcrumbTrail.ts`(2)** —— 演示数据 / 生成物 / 降级真源，理由见 §3.3。
4. **不改 `gen-menu.mjs` 生成逻辑** —— 生成物里的中文是**权威名**，不是残留。
5. **不放宽门禁口径到全角标点与带插值模板串** —— 会让 300 这个基线与台账整体重算，是**另一个决定**；
   本项只**打印**口径外处数，**不判**。
6. **不动 `R6_ALLOWED` 的 `ProductListPage.tsx` 那条**（`Price (CNY)`）—— 已判为**语义问题不是 i18n 问题**
   （reason 原文已写明「要拍板的业务文案」），不属本项，一字不动。
7. **不改 `check-i18n.mjs` 既有的四道检查**，**不处理 `en.ts` 里 18 处中文注释** —— 只在 `research.md` 登记为已知空档。
8. **不碰后端**（无端点、无 DTO、无迁移、无权限码），**不碰 `.specify/feature.json`**（共享单槽指针、gitignored、历史里没有副本）。

## 5 成功判据

- **SC-098-001（清零可核）**：`zh:check` 绿，且 `--list` 输出为 **4 个文件 / 266 处**（全部登记在册）。
- **SC-098-002（门禁有牙齿，四条分支各一个观测）**：
  - **D1 回潮**（把清零过的一处改回中文字面量）⇒ **未登记命中** ⇒ 红（**这是「防回潮」的核心**）；
  - **D2**（台账某条 `count` **加 1**）⇒ 第二分支红；
  - **D3**（台账某条 `count` **减 1**）⇒ 第三分支红；
  - **D4 归零**（文件已清零、条目只改 `count` 不删）⇒ 第三分支红（**证明「清零」是机器强制的**）；
  - **D5 扫描器退化**（摘掉 `JsxText` 分支 / 改成只认单行）⇒ `MIN_CANDIDATES.ZH` 自检失败 ⇒ 红（**反假绿有牙**）。
  每条**观测到转红**、**逐条还原**；还原判据用**内容级**（`git cat-file -p HEAD:<path> | sha1sum`），**不称「逐字节一致」**。
- **SC-098-003（界面逐字未变）**：`frontend/e2e/` 下 **444 处中文断言一行不改**且全绿。
  ⚠️ 需 8081 上有后端；**按仓规不得擅自重启可能归并行会话所有的共享后端**，没有可用后端就**不跑**，并**如实写明「未跑 e2e」**——
  **不得**用「门禁全绿」冒充「界面未变」。
- **SC-098-004（两本账一致）**：`ui:check` 绿且 R6 为 **6 条 / count 合计 8**；

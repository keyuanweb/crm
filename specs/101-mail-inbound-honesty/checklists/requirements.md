- [x] **需求可测**：每条 FR 都能指向**一条用例**（T1–T8）、**一次定向破坏**（D1–D7）或**一条可核判据**
      （`quickstart.md` §5/§6），对应关系写在 `plan.md` §验证的用例清单与 `spec.md` §5 的 SC-101-001–006。
- [x] **成功判据可核且双向（本项的核心）**：「默认不写记录」与「演示写一条记录」是**同一机制的两个方向** ——
      T2 正面断言 `total == 0`（而不是「事务会回滚所以没写」），T3 断言 `total == 1`；
      **只断 409 是弱断言**（D3 反向证明：在抛异常前先 `insert` 时，**409 照旧**、只有这两条断言能红）。
- [x] **如实声明边界（本项最重要的诚实项）**：`research.md` §13 五条 + `falsification-evidence.md` §P 六条，
      两条清单口径不同（前者=设计缺口，后者=护栏缺口与不可证项）：
      ① 演示记录的 `fromAddress` 仍是硬编码地址且**无判据能判断它是否真实**；② `demo-enabled=true` ≠ 连通性探测；
      ③ 默认拒绝让按钮必然报错（**有意**的代价，无判据能衡量用户困惑）；④ `SIMULATED` 记录不会自动清理；

      「真接 IMAP」「删端点/从清单移除」「给前端加演示模式探针」「顺手清理 `SIMULATED` 记录」

- [x] **无遗留占位符**：除 `tasks.md` 的交付块、`falsification-evidence.md` 的实测读数与预期哈希、
      `quickstart.md` §7 的读数表这类**刻意留到交付时填**的位置外，无 `TODO`/`待定` 式占位
      （**不预填未实测的数字**，这是本仓 086–100 的一贯做法）。⚠️ **破坏表不是占位符**：
      D1–D7 的「该改变哪条行为」与「该红哪条用例」在**开工前就定稿**（`tasks.md` T023 的硬要求），留空的只有读数。

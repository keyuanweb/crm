# 功能规格：国际化（i18n）模块

**功能分支**: `060-i18n`

**创建日期**: 2026-08-25

**状态**: 草稿

**输入**: 043 差距分析 P3 建议——"多语言/多时区/国际化"。对标成熟 CRM（多语言界面）：当前系统前端文案全部中文硬编码，无语言切换能力。本模块 v1 提供**语言切换框架**：前端接入 i18n（zh-CN/en），核心界面文案（系统名/导航菜单/登录页/首页）资源化，语言偏好持久化（localStorage）。

## 用户场景与测试（必填）

### 用户故事 1 - 语言切换（优先级：P0）

用户在设置中切换界面语言（中文/英文），切换后核心界面文案即时更新，偏好持久化（下次登录保持）。

**优先级理由**: 语言切换是国际化核心交互，P0 最先交付。

**独立测试**: 切换英文 → 系统名/菜单/登录页变英文 → 刷新保持。

**验收场景**:

1. **Given** 登录系统，**When** 切换语言为 English，**Then** 系统名/导航菜单/顶栏文案立即变英文。
2. **Given** 语言切换后，**When** 刷新页面，**Then** 语言偏好保持（English）。
3. **Given** 切换回中文，**When** 查看，**Then** 文案恢复中文。

---

### 用户故事 2 - 核心文案资源化（优先级：P0）

核心界面文案（系统名、菜单分组与项、登录页、顶栏、首页问候）改为 i18n key 驱动，中英双语资源。

**优先级理由**: 资源化是语言切换的基础，与故事 1 共同构成 P0。

**独立测试**: 核心页面文案随语言变化。

**验收场景**:

1. **Given** 核心文案资源化，**When** 切换语言，**Then** 系统名/菜单/登录页/首页显示对应语言。
2. **Given** 英文资源缺失的 key，**When** 切换英文，**Then** 回退中文（不白屏）。

### 边界情况

- 语言偏好默认 zh-CN（现有用户无偏好）。
- 未翻译 key 回退中文。
- 仅核心界面资源化（业务页面文案渐进迁移，v1 不覆盖全部页面）。

## 需求（必填）

### 功能需求

#### 语言切换

- **FR-I01**: 系统必须支持界面语言切换（zh-CN / en）。
- **FR-I02**: 语言偏好必须持久化（localStorage）。
- **FR-I03**: 切换后核心界面文案即时更新。

#### 资源化

- **FR-I04**: 系统名/导航菜单（分组与项）/登录页/顶栏/首页核心文案必须 i18n key 驱动。
- **FR-I05**: 未翻译 key 必须回退中文。

#### 权限与约束

- **FR-I06**: 语言切换对全部用户开放（登录页 + 登录后设置）。

### 关键实体（涉及数据）

- 无新增实体。涉及文件：`frontend/src/i18n/`（初始化 + zh/en 资源）、`App.tsx`（菜单文案）、登录页、首页。

## 成功标准（必填）

### 可度量结果

- **SC-I01**: 语言切换即时生效（抽查 5 个界面元素）。
- **SC-I02**: 偏好持久化（刷新后保持，抽查 3 次）。
- **SC-I03**: 核心页面中英双语资源齐全（对照清单核对 1 次）。
- **SC-I04**: 前端 typecheck / lint / build 通过，无回归。

## 假设

- v1 用 react-i18next（或等效轻量方案）。
- 业务页面文案渐进迁移（v1 覆盖核心框架 + 导航 + 登录/首页）。
- 时区处理不在 v1（时间显示保持服务器时区）。

## 依赖

- 无新增后端依赖；前端框架注入。

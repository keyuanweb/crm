# Feature Specification: 批量导入增强（线索/联系人导入）

**Feature Branch**: `024-bulk-import`

**Created**: 2026-08-23

**Status**: Draft

**Input**: User description: "批量导入增强：线索与联系人 Excel 批量导入，复用客户导入模式（模板下载/解析校验/结果反馈），提升数据录入效率"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 线索批量导入 (Priority: P1)

管理员或销售可从线索列表页下载 Excel 模板，按模板格式批量录入线索（姓名、公司、职位、电话、邮箱、来源、评分、备注），上传后系统解析、校验并导入；导入结果反馈成功/失败明细（含行号与原因）。

**Why this priority**: 线索录入是销售启动的高频动作，批量导入可大幅减少手工录入成本；客户导入（016）已有成熟模式，线索导入复用该模式成本低、价值高。

**Independent Test**: 可独立验证——下载模板填写 3 行（2 行合法 1 行缺公司名），上传后导入 2 行成功、1 行失败并指出行号原因。

**Acceptance Scenarios**:

1. **Given** 用户下载线索导入模板，**When** 打开文件，**Then** 包含姓名/公司/职位/电话/邮箱/来源/评分/备注列。
2. **Given** 用户上传含合法数据的模板（姓名+公司必填），**When** 提交导入，**Then** 合法行导入成功，返回成功数。
3. **Given** 某行缺少必填字段（如公司为空），**When** 提交导入，**Then** 该行标记失败并注明原因与行号，其余行正常导入。

### User Story 2 - 联系人批量导入 (Priority: P1)

管理员或销售可从联系人列表页下载模板，按模板批量导入联系人（姓名、客户、职位、电话、邮箱、角色、备注），上传后解析导入并反馈结果。

**Why this priority**: 联系人数据通常伴随客户批量录入（如从旧系统迁移），批量导入降低迁移成本。

**Independent Test**: 可独立验证——模板填写联系人与客户名，上传后成功导入并关联到对应客户。

**Acceptance Scenarios**:

1. **Given** 用户下载联系人导入模板，**When** 打开文件，**Then** 包含姓名/客户名称/职位/电话/邮箱/角色/备注列。
2. **Given** 用户上传含合法数据（姓名+客户名称必填），**When** 提交导入，**Then** 联系人导入成功并关联到匹配客户。
3. **Given** 某行客户名称在系统中不存在，**When** 提交导入，**Then** 该行标记失败并注明"客户不存在"。

### User Story 3 - 导入反馈与错误处理（可选） (Priority: P2)

导入失败明细下载（含行号与原因的文本/Excel），方便批量修正后重新导入。

**Why this priority**: 大批量导入时失败行可能很多，提供失败明细文件让用户离线修正。

**Independent Test**: 可独立验证——导入含失败行的文件后，下载失败明细包含对应行号与原因。

**Acceptance Scenarios**:

1. **Given** 导入结果含失败行，**When** 点击下载失败明细，**Then** 文件包含行号、原始数据与失败原因。

### Edge Cases

- 空文件或无数据行：返回"无有效数据"而非报错。
- 非法来源/评分（如来源不在枚举、评分 >100）：该行失败并注明。
- 重复数据（同名同公司线索）：按既有唯一性规则（若存在则提示重复）。
- 文件类型非 xlsx：返回明确错误。
- 数据权限：导入的线索/联系人归属当前用户（created_by）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须提供线索导入模板下载（Excel xlsx），包含姓名/公司/职位/电话/邮箱/来源/评分/备注列。
- **FR-002**: 系统必须支持线索 Excel 批量导入：解析、校验（姓名/公司必填、来源/评分合法）、逐行导入，返回成功/失败明细（行号+原因）。
- **FR-003**: 系统必须提供联系人导入模板下载，包含姓名/客户名称/职位/电话/邮箱/角色/备注列。
- **FR-004**: 系统必须支持联系人 Excel 批量导入：按客户名称匹配客户并关联，校验（姓名/客户名称必填），返回结果明细。
- **FR-005**: 导入失败明细必须可下载（含行号、原始数据、失败原因）。
- **FR-006**: 导入必须记录审计日志（谁在何时导入了多少条）。
- **FR-007**: 导入的线索/联系人 created_by 为当前用户；数据权限遵循既有规则。
- **FR-008**: 非 xlsx 文件或空文件必须返回明确错误，不产生部分导入。

### Key Entities

- **线索/联系人导入（BulkImport）**: 复用 ImportResult 结构（successCount/failureCount/failures）与 POI 解析，无新表。
- **导入模板（ImportTemplate）**: 生成的 xlsx 模板（表头列），按实体生成。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 线索导入正确率 100%——10 行合法数据全部导入成功，字段值正确。
- **SC-002**: 校验正确率 100%——5 行非法数据（缺必填/非法枚举）全部标记失败并注明原因。
- **SC-003**: 联系人导入关联正确率 100%——按客户名称匹配关联（抽查 10 次）。
- **SC-004**: 失败明细下载内容与页面结果一致率 100%（抽查 5 次）。
- **SC-005**: 空文件/非 xlsx 文件拒绝率 100%（返回明确错误）。

## Assumptions

- 复用 016 客户导入的 POI 解析与 ImportResult 结构，扩展 LeadExcelService / ContactExcelService。
- 线索必填：姓名+公司；联系人必填：姓名+客户名称（客户按名称匹配，不区分大小写精确匹配）。
- 导入的线索/联系人归属当前用户（created_by）；线索评分沿用 019 自动评分（导入时可带 score，导入后可选重算）。
- 失败明细下载为简单文本/Excel 文件。
- 导入接口仅 ADMIN 与本人（SALES 可导入，归属本人）。

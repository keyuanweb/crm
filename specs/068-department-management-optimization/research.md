# Research: 部门管理页面优化

## 技术决策

### 1. 前端树形组件选择

**决策**: 使用 Ant Design Tree 组件

** rationale**: 
- 项目已使用 Ant Design 5.22.0
- Tree 组件原生支持展开/收起、搜索高亮、自定义节点
- 无需引入额外依赖
- 符合项目前端开发规范

**替代方案**: 
- 自定义递归组件：开发成本高，维护复杂
- 第三方树形库：增加依赖，不符合规范

### 2. 搜索实现方式

**决策**: 前端搜索（全量加载 + 客户端过滤）

**Rationale**:
- 部门数据量小（< 1000 条），全量加载性能好
- 避免增加后端搜索 API
- 搜索响应时间 < 200ms 易达成
- 符合约束条件"无新增后端 API"

**替代方案**:
- 后端分页搜索：需要新增 API，违反约束
- 懒加载：用户体验差，不符合优化目标

### 3. 缓存策略

**决策**: 部门树缓存（TTL 30 分钟）

**Rationale**:
- 部门数据变更频率低
- 符合宪法原则 4 缓存策略
- 缓存 key 格式：`crm:department:tree`
- 更新策略：先更新数据库，再删除缓存

**替代方案**:
- 不缓存：每次请求查数据库，性能差
- 更长 TTL：部门变更无法及时生效

### 4. 分页实现

**决策**: 前端分页（树形节点展开后分页）

**Rationale**:
- 树形结构分页复杂，用户体验差
- 部门数据量小，前端分页可行
- 符合性能目标

**替代方案**:
- 后端分页：树形结构分页困难，需要返回完整路径
- 不分页：1000 个部门时页面过长，不符合 UX 优化目标

## 已知问题

### 1. 树形结构分页

**问题**: 树形结构分页复杂，展开/收起状态难以保持

**解决方案**: 
- 采用前端全量加载 + 虚拟滚动（Ant Design Tree 支持）
- 或采用分页加载（每页 20 个顶级部门）

**推荐**: 前端全量加载 + 搜索过滤（数据量小时）

### 2. 部门名称唯一性

**问题**: 部门名称在相同上级部门下唯一，但现有 API 未校验

**解决方案**:
- 后端增加唯一性校验（在 create/update 时检查）
- 前端增加实时校验（失焦时检查名称是否已存在）

**实现**: 后端 DepartmentService.create() 和 update() 方法中增加校验

## 结论

所有技术决策已确定，无 NEEDS CLARIFICATION 项。

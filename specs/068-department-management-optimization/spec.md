# Feature Specification: 部门管理页面优化

**Feature Branch**: `068-department-management-optimization`

**Created**: 2026-08-29

**Status**: Draft

**Input**: 用户描述："部门管理页面页面和逻辑优化，要符合 sdd 开发规范，中间需要确认的你自己定，知道开发执行完成"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 部门树形列表与搜索（Priority: P1）

管理员能够以树形结构查看部门列表，支持按部门名称关键字搜索，快速定位目标部门。

**Why this priority**: 当前系统仅有基础树形展示，缺乏搜索功能；部门数量增长后需要检索入口；作为 P1 最先交付。

**Independent Test**: 在已有部门数据的系统中可独立验证搜索、筛选功能。

**Acceptance Scenarios**:

1. **Given** 系统存在多个部门，**When** 管理员输入关键字"销售"搜索，**Then** 仅返回名称包含"销售"的部门及其父子关系
2. **Given** 部门列表超过一页，**When** 管理员切换页码，**Then** 当前页数据正确显示且搜索条件保持
3. **Given** 搜索无结果，**When** 管理员清除搜索关键字，**Then** 恢复显示完整部门树

---

### User Story 2 - 部门创建与编辑（Priority: P1）

管理员能够创建新部门（名称、上级部门、描述、排序号），并编辑已有部门信息。

**Why this priority**: 部门 CRUD 是核心功能；与故事 1 共同构成 P1 基础能力。

**Independent Test**: 在已有部门数据的前提下可独立完成创建、编辑操作。

**Acceptance Scenarios**:

1. **Given** 管理员已登录，**When** 管理员创建新部门（名称"测试部门"、上级部门"技术部"、描述"测试用"、排序号 10），**Then** 系统返回成功且新部门显示在树形列表中
2. **Given** 部门名称已存在，**When** 管理员再次创建同名部门，**Then** 系统拒绝并提示名称已存在
3. **Given** 部门"测试部门"已存在，**When** 管理员编辑其描述为"更新后的描述"，**Then** 保存成功后显示新描述

---

### User Story 3 - 部门删除与防护（Priority: P2）

管理员能够删除空部门（无子部门、无成员）；系统自动防护删除有子部门或成员的部门。

**Why this priority**: 部门删除是日常运维必需；依赖故事 1、2 的部门数据，故列为 P2。

**Independent Test**: 在已有部门数据的前提下可独立完成删除操作及防护验证。

**Acceptance Scenarios**:

1. **Given** 部门"测试部门"无子部门且无成员，**When** 管理员删除该部门，**Then** 删除成功且树形列表刷新
2. **Given** 部门"技术部"有子部门"前端组"，**When** 管理员尝试删除"技术部"，**Then** 系统拒绝并提示"该部门存在子部门，无法删除"
3. **Given** 部门"销售部"有成员"张三"，**When** 管理员尝试删除"销售部"，**Then** 系统拒绝并提示"该部门存在成员，无法删除"

---

### User Story 4 - 部门详情查看（Priority: P2）

管理员能够查看部门详情（名称、上级部门、描述、创建时间、创建人、成员数量、子部门数量）。

**Why this priority**: 部门详情提供完整信息视图；依赖故事 1 的部门数据，故列为 P2。

**Independent Test**: 在已有部门数据的前提下可独立验证详情查看功能。

**Acceptance Scenarios**:

1. **Given** 部门"技术部"已存在，**When** 管理员点击"查看详情"，**Then** 弹出详情面板显示部门完整信息
2. **Given** 部门详情面板已打开，**When** 管理员关闭面板，**Then** 面板关闭且状态重置

---

### Edge Cases

- 部门名称允许空格和特殊字符，但前后空格自动去除
- 删除操作需要二次确认，防止误删
- 上级部门不能设置为自身或自身的子孙部门（防环）
- 部门树最多支持 5 层嵌套（性能考虑）
- 搜索关键字为空时显示完整树形结构

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须支持树形结构展示部门列表，支持展开/收起子部门
- **FR-002**: 系统必须支持按部门名称关键字搜索，支持模糊匹配
- **FR-003**: 系统必须支持分页显示部门列表（默认 20 条/页）
- **FR-004**: 系统必须支持创建部门，字段包含名称（必填）、上级部门（可选）、描述（可选）、排序号（可选，默认 0）
- **FR-005**: 系统必须支持编辑部门（名称、上级部门、描述、排序号）
- **FR-006**: 系统必须支持删除部门，但禁止删除有子部门或成员的部门
- **FR-007**: 系统必须支持查看部门详情（名称、上级部门、描述、创建时间、创建人、成员数量、子部门数量）
- **FR-008**: 系统必须保证部门名称在相同上级部门下唯一
- **FR-009**: 系统必须防止部门环（上级部门不能是自身的子孙）
- **FR-010**: 系统必须限制部门树最大深度为 5 层

### Key Entities *(include if feature involves data)*

- **部门（Department）**: 已有实体扩展；属性包括名称（唯一约束按上级部门）、上级部门（自引用）、描述（可选）、排序号（整数，默认 0）、创建时间、创建人、成员数量（计算字段）、子部门数量（计算字段）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 管理员能在 30 秒内完成一个新部门的创建（从打开表单到保存成功）
- **SC-002**: 部门搜索响应时间 < 200ms（1000 个部门数据量下）
- **SC-003**: 删除防护拦截率 100%（有子部门或成员的部门无法删除）
- **SC-004**: 90% 的管理员能在一分钟内找到目标部门（搜索 + 树形结构）

## Assumptions

- 部门管理仅管理员（ADMIN 角色）可见和操作
- 部门树全量加载（不采用懒加载），适用于 1000 个部门以内的场景
- 部门描述字段最大长度 500 字符
- 排序号用于控制同级部门的显示顺序，值越小越靠前
- 创建人显示用户名（非 ID），通过用户 ID 关联查询
- 成员数量实时计算（不缓存），子部门数量预计算缓存
- 前端使用 Ant Design Tree 组件展示树形结构
- 后端 API 保持不变（复用现有的 `/api/v1/departments/tree` 等接口）

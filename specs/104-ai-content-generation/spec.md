## 背景与上游

**本项上游不是比对清单的某一条缺口，而是两个事实的合流：**

1. `CRM_FEATURE_COMPARISON.md` **2.10 AI 能力** 是全书**唯一一个「八项判定无一项变化」的能力域**，判定 **1.5 / 5**，原文自述本项目 AI 能力实质为「**规则引擎 + 统计**」，与业界「AI 原生 CRM」存在**代际差**；Gartner 2025 已将「原生 AI/ML 覆盖至少 3 项核心功能」列为评估门槛。差距清单中列为 **P1 第 8 项「AI 能力空白」**。
2. 用户**实测确认**该域为真空白：`openai` / `llm` / `anthropic` / `dashscope` / `qwen` / `deepseek` / `embedding` / `langchain` / `ollama` 在 `backend/src/main/java` + `backend/pom.xml` + `frontend/src` + `frontend/package.json` **逐项零命中**（2026-09-27 复跑，非引用 09-14 快照），`/ai/` 端点零命中。

### ⚠️ 与 022 的关系（**必读，否则会误判本项性质**）

本仓库**已经有一个叫「AI 助手」且被标 ✅ 的功能**：`specs/022-ai-assistant/`，实现为 `SuggestionService` + `SuggestionController` + `SuggestionCenterPage`。它**不是 AI**，其 `tasks.md:61` 自述「智能建议为**规则引擎（非 LLM）**」，spec 明文「**不引入外部 AI 服务**」。它是确定性的规则聚合。

⇒ **本项不是给 022 加功能，而是从零引入模型依赖。** 两者关系：022 保留不动（它是规则型，永远可用、零成本、无外部依赖），本项是**新增一条独立的、可关闭的生成式路径**。**不得**把 022 改造掉、**不得**让 022 依赖本项。

**命名空间互斥（易撞）**：`ai:` 前缀**已被 022 占用**（`SuggestionService.java:36` 的 `ai:ignore:` 忽略集）。本项的 Redis 键一律走 **`ai:gen:*`**，两族不得混用。

## 用户场景与测试 *(mandatory)*

### 用户故事 1 - 邮件草稿生成 (Priority: P1)

销售在客户/商机上下文里点「AI 生成草稿」，系统基于**当前可见的**客户与商机信息产出一封邮件正文草稿，插入既有编辑区供人工修改；销售确认后才通过**既有发送路径**发出。

**Why this priority**: 邮件是这个 CRM 已闭环的链路（模板 + 群发 + 发送日志 + 追踪 + 退订），缺的正是"从零写一封"这一步。它的输入是页面上已有的数据，输出是**给人工审阅的文本**，不进库、不自动发送 ⇒ **不产生新的持久化状态、不引入新的写路径**，是四项里风险最低、判据最好写的一项。**若本批需要拆分交付，P1 可单独成立。**

**Independent Test**: 可独立验证——在已配置模型的隔离实例上，对某客户发起生成，返回非空纯文本且**长度与格式落在契约区间**；未配置模型时同一入口返回 **409 `AI_NOT_CONFIGURED`**；把模型端点指向不可达地址时返回**受控错误码**而非 500，且编辑区仍可手工输入。

**Acceptance Scenarios**:

1. **Given** 模型已配置且可用，**When** 销售在某客户详情页点「AI 生成草稿」，**Then** 返回一段邮件正文草稿并填入编辑区，**且**在一次请求内不产生任何对客户/商机数据的写入（`AuditService` 之外零写）。
2. **Given** 模型**未**配置（`crm.ai.enabled=false` 或缺 base-url），**When** 点同一按钮，**Then** 返回 **409** 且 code 稳定，**且出站请求数与新增记录数均为 0**（正面断言，不得只靠事务推理）。
3. **Given** 模型端点可达但返回 429/超时，**When** 生成，**Then** 返回受控错误码（非 500），前端展示可读失败文案，**且**编辑区保留用户已输入内容。
4. **Given** 该销售的角色对客户 `amount` 字段**无读权限**（102 的字段级权限），**When** 生成，**Then** 草稿中**不出现**该字段的值。

### 用户故事 2 - 客户 360 摘要 (Priority: P2)

销售在客户详情页点「AI 摘要」，把该客户跨 Tab 的信息（基本/标签/概览/订单/回款/合同/工单 + 跟进时间线）压成一段结构化中文摘要。

**Why this priority**: 复用同一套客户端与降级路径，增量只在提示词与放置位置；判据易写（结构断言 + 字段级权限断言）。

**Independent Test**: 可独立验证——有订单/回款/工单数据的客户，摘要包含对应小节；无数据的客户摘要不编造小节；对无权限字段，摘要中零出现。

**Acceptance Scenarios**:

1. **Given** 某客户有订单与回款但无工单，**When** 生成摘要，**Then** 输出含订单与回款小节、**不含**工单小节，**且**不出现"无数据"以外的编造内容。
2. **Given** 该客户一条数据都没有（新客户），**When** 生成摘要，**Then** 返回受控的"信息不足"结果而非空字符串或幻觉内容。

### 用户故事 3 - 跟进记录润色 / 总结 (Priority: P3)

销售写完一条跟进记录后点「AI 润色」，把口语化文本整理为结构化、可读的记录；或把多条历史跟进总结为一段。

**Why this priority**: 实用，但输入是自由文本，提示词工程量最大、判据最难写（"润色得好不好"难以断言）。

**Independent Test**: 可独立验证——输入含错别字/口语的文本，输出为规范化文本且**语义关键要素（客户名、时间、结论）逐项保留**；空输入被拒绝（422）。

**Acceptance Scenarios**:

1. **Given** 输入文本含具体日期与客户名，**When** 润色，**Then** 输出中该日期与客户名**逐字仍在**（防"改写丢信息"）。
2. **Given** 输入为空或超长（超过契约上限），**When** 润色，**Then** 分别返回 422 受控错误，**且不发起出站请求**。

### 用户故事 4 - 商机下一步建议 (Priority: P4)

在商机详情页基于阶段、停滞天数、历史转化率给出"下一步做什么"的建议文本。

**Why this priority**: 022 已有**阶段模板版**的"下一步最佳行动"（比对报告 2.10 判定 ⚠️「规则/清单，无个性化推荐」）。本项是其**升级**，不是新增能力 ⇒ 必须与 022 的既有行为划清边界，否则会造成"同一页两套建议、互相矛盾"。

**Independent Test**: 可独立验证——同一商机在两个不同阶段得到不同建议文本；建议文本**不得**直接下结论为事实（须为建议语气，见 FR-011 的约束）。

**Acceptance Scenarios**:

1. **Given** 商机处于 `INITIAL_CONTACT` 且停滞 30 天，**When** 请求建议，**Then** 返回建议文本，**且**该建议与 022 阶段模板建议在同一页面上**有明确的视觉区分**（不得两个都叫"下一步建议"而无标识）。

### 边界情况

- **模型返回空/截断**：须可判定。`max_tokens` 触顶 ⇒ 记 `truncated` 状态并提示，不得静默返回半截文本当完整结果。
- **模型拒答**（safety/refusal）：须与网络错误区分，返回受控文案，不得 500。
- **并发**：同一用户连点两次生成 ⇒ 由限流与预算拦截，不得并发烧两次。
- **数据范围**：所有输入取数**必须**经过既有数据范围与字段级权限过滤（见 FR-010）；**本条是本项最大的安全面**。
- **超长上下文**：客户数据超过提示预算时须**截断并告知**，不得静默丢弃（比对报告 Common Pitfalls 同旨）。
- **未配置即默认**：`crm.ai.enabled` 默认 **false**，且"默认路径零出站、零记录"必须有**正面断言**看着（022/101 的教训：默认路径的副作用往往无断言）。

## 需求 *(mandatory)*

### 配置与门

- **FR-001** 配置项：`crm.ai.enabled`（**默认 `false`**）、`crm.ai.base-url`、`crm.ai.api-key`、`crm.ai.model`（默认 `claude-opus-5`）、`crm.ai.max-tokens`、`crm.ai.timeout-seconds`（默认 60）。 ✅ **2026-09-27 C4：本条实为**七**项——随 FR-015/FR-017 的日预算闸落地补第 7 项 `crm.ai.daily-token-budget`（默认 `100000`）。上面那六项逐字保留；新增项同样受 FR-002 的"`application.yml` 默认值与 `@Value` 兜底逐字一致"约束（两处都写 `${CRM_AI_DAILY_TOKEN_BUDGET:100000}`）。⚠️ "六项"这个计数在 `application.yml`、`tasks.md` T014、本条三处各写了一遍，三处已同批改为七项——只改一处等于用一次订正造出两处新矛盾。**
- **FR-002** 判定"是否已配置"的**唯一判据源**是一个状态类（照 `MailInboundStatus` 体例，javadoc 自称唯一判据源）；`application.yml` 的默认值与 Java `@Value` 的兜底值**必须逐字一致**。
- **FR-003** 未配置时：端点返回 **409**、code 稳定（照 `MAIL_INBOUND_NOT_CONFIGURED` 体例，**不发明 501**——全仓零先例），**且不发起任何出站请求、不写任何记录**；此两条须为**正面断言**（单测 `verify(..., never())` + IT 计数为 0）。
- **FR-004** **密钥处理**：`api-key` 只经配置层读取；**不得**出现在日志、响应体、审计 detail、异常消息中。缺密钥与格式错误须区分（照 `SecurityDefaultsGuard`：空 = 合法但告警，有值但畸形 = 启动即失败）。
- **FR-005** **出站白名单**：`base-url` 的主机必须在 `crm.outbound.allowed-hosts` 内。因该 URL 来自**部署配置而非用户输入**，校验时机是**启动期一次**（不逐跳）；未列入时须**启动即失败并给出可操作的错误信息**，而不是运行期才发现。

### 客户端

- **FR-006** 使用**官方 Java SDK**（`com.anthropic:anthropic-java`），**不手搓 HTTP**、**不引入 OpenAI 兼容层**。理由：SDK 自带重试、超时、typed 异常与 usage 计数，手搓会丢掉这些且难以对齐错误语义。
- **FR-007** ⚠️ **已知架构冲突（须在 plan 中处置）**：SDK 内部走 OkHttp，**绕过**共享 `RestTemplate` ⇒ **不经过 `OutboundUrlValidator` 的逐跳校验**。本项以 FR-005 的启动期校验替代，依据是威胁模型不同（Webhook 的 URL 来自用户数据；本项的 base URL 来自运维配置）。**此偏离必须在 `plan.md` 的 Constitution Check 中显式声明并说明理由**，不得静默绕过。
- **FR-008** **非流式**调用（流式为明确的非目标，见下）。服务端超时由 FR-001 配置；**不得**受前端 30s 全局超时约束（前端走既有 `timeout: 0` 逃生口，`apiClient.ts:36`）。
- **FR-009** 系统提示词（稳定、可缓存）与用户提示词（含客户数据）**必须分离**：客户数据一律进 user 消息，**不得**进 system。

### 输入与输出（安全面）

- **FR-010** **取数必须经既有过滤链**：所有输入数据由**已应用数据范围过滤与字段级权限（102 FLS）的服务层**读取得出。**严禁直查裸 Mapper** —— 这正是 022 已存在的缺陷（`SuggestionService.java:87-92/110-115/150-154` 三条规则直查 `SalesOpportunityMapper`/`FollowUpMapper`/`LeadMapper`，而 `MybatisPlusConfig.java:19-24` 只注册了分页与乐观锁两个拦截器，**全仓无数据权限拦截器**），本项**不得重蹈**。
- **FR-011** 每项能力**必须逐项列出送入模型的字段白名单**（写在 `contracts/` 里）。默认**不含**：联系电话、邮箱、身份证件、银行/回款账号等直接标识符（除非该项能力确有需要且逐字段论证）。
- **FR-012** 输出按**纯文本**处理：服务端**不得**执行输出中的任何指令 ⇒ **不注册工具、不发二次网络请求、不拼 SQL**。输出渲染到前端前须与既有渲染路径同等对待（防注入）。
- **FR-013** **字段级权限一致性**：生成结果**不得**泄露发起者无权读的字段值。这是 US1-AS4 / US2-AS2 的判据来源。

### 成本与滥用

- **FR-014** 每个生成端点**必须**带 `@RateLimit`（或进入豁免清单并附**非空书面理由**）——`RateLimitCoverageTest` 是字节码台账，漏一个即转红。
- **FR-015** 每用户/每日 token 预算，Redis 键走 **`ai:gen:*`**（与 022 的 `ai:ignore:` 分离）。
- **FR-016** 每次调用记录：模型名、**输入/输出 token 数（取自 SDK 返回的 usage，不得估算）**、耗时、发起人、能力名，写入既有审计机制（`AuditService.record`）。**detail 中不得含提示词原文与客户数据。**
- **FR-017** 预算耗尽 ⇒ 受控 429（复用既有 `RATE_LIMITED` 语义），不得静默失败。

- **FR-019** 生成结果**不落库**：插入既有编辑区，经**既有保存路径**持久化。本项**零新增表**（除 FR-020 的权限码迁移外零迁移）。

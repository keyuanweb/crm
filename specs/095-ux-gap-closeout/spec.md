本项就是那一项。同时它要消化实施勘察阶段**新发现的两类事实**：① 清扫自己的判断里有 **3 处经复核不成立**；② `068` 有一条**规格级**的自相矛盾（`FR-003` 与 `research.md` §4 相反）——用户已裁决**订正**而非实现。

### 推翻既有登记的三处（本次实测，全部为「原记录不成立」）

登记表上的 ✅ 不等于做了，**登记表上的 ⚠️ 也不等于就是真的**。以下三处是本次复核**推翻了原有记录**的，一律**原文留痕 + 带日期订正**，且**不因一个不存在的原因去改代码**：

1. **「`t` 被遮蔽」＝假阳性**。`DepartmentListPage.tsx` 的 086 注释称 `load()` 里 `const t = await fetchDepartmentTree()` 遮蔽了 i18n 的 `t`、导致加载失败时用户看不到提示。**不成立**：`const t` 声明在 `try` **块**内，`catch` 是**平级**块作用域，`catch` 里的 `t` 解析到组件顶层的 i18n `t`（已用 node 复现同形结构自证）。**订正注释，代码一行不改。**
2. **「`walk` 未防 `children` 缺失」的触发条件不成立**。后端 `DepartmentResponse.children` 初始化为 `new ArrayList<>()`（恒非 null），且 `application.yml` 是 `default-property-inclusion: non_null` 而**空数组仍会序列化** ⇒ `children` 恒为数组。同一注释的后半句一并订正，**代码一行不改**。
3. **`067` 的 T001（逐节点默认样式值）不是缺口**。`FlowNode` 的 `shadow?`/`borderRadius?`/`hoverHighlight?` **只有声明处本身**，全仓无任何节点赋值、无任何读取方；而 `spec.md` 的 FR-001 判据（节点有阴影/圆角/悬停）由页面级**统一默认样式**满足，spec 全文**没有逐节点要求**。⇒ 逐节点补值＝造无人消费的死数据（088 刚清过真孤儿）。**订正，不补做。**

### 为什么 T033/T034 是「订正」而不是「实现」

`068` 的 T033（详情加载态）与 T034（详情错误处理）要求详情面板有可观测的加载中与失败窗口。实测：

- 详情的数据来源是 `openDetail(row) → setDetailData(row)`，即**列表里已加载的那一行的同引用**，**同步完成**；
- 后端 `DepartmentResponse` 已含 `createdAt`/`createdBy`（已解析成用户名）/`memberCount`/`childCount` ⇒ **FR-007 要的 7 个字段全在树里**，不存在「详情缺字段所以要再取一次」；
- 后端**没有** `GET /departments/{id}`（只有 `GET /tree`、`POST`、`PUT /{id}`、`DELETE /{id}`），而 `068` 的 `plan.md` 明文「**无新增后端 API／复用现有接口**」。

⇒ 这两条要求的前提（详情独立取数）与本项的设计形态**结构性冲突**。为满足字面而去新增一个只为显示「本来就有的数据」而往返一次的端点，是**制造假加载态**——同 `068` 的 T028（加前端 `console.log`）性质：**加了才是退步**。**按现状订正为「不适用」，不补做。**

## 用户故事与验收

### 故事一：搜索部门时，我看得见「命中在哪」，也不再打个字就哆嗦

管理员在部门树里搜「华东」。**今天**：只有节点被过滤掉/留下，命中在名称的哪个位置得自己找；每敲一个字符整棵树立刻重算；搜不到任何结果时页面只剩一片空白，分不清「没有这个部门」与「还没加载」。

**验收**

1. **Given** 树里有「华东销售部」，**When** 输入「华东」，**Then** 「华东」二字在节点标题里被标出（`<mark>`），且**过滤结果与高亮用的是同一个关键词值**。
2. **Given** 正在连续输入，**When** 逐字符敲完「华东销售部」，**Then** 过滤**不在每个字符后都重算**，而是停止输入一段时间后算一次；且**最终结果与不防抖时一致**。
3. **Given** 树存在，**When** 输入一个不匹配任何部门的词，**Then** 显示明确的**空状态**（不是空白）。
4. **Given** 搜索框已清空，**When** 树重新渲染，**Then** 此前算好的展开结构**不再被无条件清空**（今天每次加载后展开态都会被一个 effect 抹掉，与 `load()` 的意图相反）。

### 故事二：看详情、删部门时不必靠猜

**今天**：详情面板是一大坨直接写在页面文件里的 DOM；在窄窗口下它仍是一个桌面弹窗；删除确认只问一句「确定删除部门「X」吗？」，**不说删了会怎样**——而「有子部门或成员时删除会被拒绝」是后端真会执行的一条规则；页面上没有任何 `aria-` 属性。

**验收**

1. **Given** 一个部门，**When** 点「查看详情」，**Then** 详情由一个**独立组件**渲染（页面文件里不再内联九项字段）。
2. **Given** 窗口足够宽 / 很窄，**When** 打开详情，**Then** 分别使用**对话框**与**底部抽屉**两种形态（移动端可用性）。
3. **Given** 一个带 3 个子部门、12 名成员的部门，**When** 点删除按钮，**Then** 确认框里显示**这两个真实数字**并说明「有子部门或成员时删除会被拒绝」，而不是一句通用警告。
4. **Given** 键盘/读屏用户，**When** 进入本页，**Then** 搜索框与树容器有可被朗读的名称；树的节点具备可聚焦的结构前提（**方向键行为本身不经本项验证**，见「假设」）。

### 故事三：地图上「已驳回 / 已终止」的红色警示不再无人守

`067` 的 T009 要求「状态流转异常状态红色警示」有用例。实测这条**完全可测且无需改生产代码**：页面的 G6 配置被测试里的 mock 构造器自动记录，红色边框的判据（`stroke` 三元与 `lineWidth` 三元）就在那份被记录的配置里。

**验收**

1. **Given** 打开使用地图的状态流转页，**When** 取被记录的图节点样式函数，**Then** 对 `warning: true` 的节点返回红色边框与更粗的线宽；对普通节点返回原色与常规线宽（**同一条用例里做对照**，防判据恒真）。
2. **Given** 本项是纯测试补齐，**Then** 生产代码**一行不改**。

### 故事四：这四类欠账如实收口，不留悬案

**验收**

1. `068` 的 `FR-003`（分页）、US1 的验收场景 2、`research.md` §4 的「前端分页」决策——**同一事实的三处表述**——一并订正，原文保留。
2. `068` 的 T033/T034、`067` 的 T001、`DepartmentListPage.tsx` 的 086 注释，各自就地订正。
3. 两处登记（模块表 + 路线图）更新。
4. **不**回填 `067`/`068` 的历史勾选行。

## 假设

- **antd 锁定 5.22.0**：`destroyOnClose` 是本版**正确**拼写，不得改成更高版本才引入的 `destroyOnHidden`（改了会静默失效）。
- **测试环境没有布局引擎**（jsdom）且 `src/test/setup.ts` 把 `matchMedia` **恒桩成 `matches: false`** ⇒ `Grid.useBreakpoint().lg` 恒假、`isMobile` 恒真。故：①断点的**两个分支必须各有一条独立断言**，且桌面分支须**在测试文件内**覆盖 `matchMedia` 才能跑到（范式见 `UsageMapPage.test.tsx`）；②本项断到的是**结构与配置值**，移动端抽屉的真实排版、方向键的真实行为**未被自动化验证**，只记作「结构前提已断言」。
- **i18n 键缺失会直接抛错**：`setup.ts` 的 `react-i18next` mock 查不到键即抛；`i18n:check` 另做双语双向比对。故新增键必须**同一次提交**进 `zh-CN.ts` 与 `en.ts`。
- **本仓常有多个会话共用同一工作区**：提交一律**逐路径 `git add`**，禁用 `git add -A`；提交前先查并行会话。
- **e2e 打的是「已在跑的后端」**：本项不产出 e2e 证据，故不涉及。

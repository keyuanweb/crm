# Quickstart: 067/068 真缺口收口（095）

本文件是**可跑的**验证路径：门禁怎么跑、手工冒烟看哪几处、以及**哪些结论本项不声称**。

## 0. 前置

纯前端改动，**不需要后端**（本项零后端改动、无迁移）。但**手工冒烟**需要后端在跑（页面要真的取到部门树）。

> **关于「已在跑的后端」**：本仓多会话共用工作区，**不重启可能属于并行会话的后端**。冒烟时打的就是当前监听在 8081 的那个实例——本项不改后端，故**不做**「后端是不是本次改动编译出来的」这项核对（本项对后端字节码零要求）。这条口径在本项**不构成缺口**，如实写在此处是为了避免读者误以为做过该项核对。

```bash
cd frontend
pnpm install --frozen-lockfile   # 若 node_modules 已在可跳过
```

## 1. 七道门禁（本项的主判据）

```bash
cd frontend
pnpm typecheck && pnpm lint && pnpm i18n:check && pnpm menu:check && pnpm perms:check && pnpm ui:check && pnpm test:coverage
```

逐道看什么：

| 门禁 | 期望 | 本项为什么会被它拦 |
|---|---|---|
| `typecheck` | 退出码 0 | 新组件/新 hook 的类型 |
| `lint` | 退出码 0（**无 `--max-warnings`**） | `react-refresh/only-export-components`（warn）——页面文件里导出组件会命中，这正是 `Highlight` **必须提取**而非就地 export 的原因 |
| `i18n:check` | 退出码 0，双语**双向**比对 | 新增的 `confirmDeleteRisk` 与各 `aria-label` 键必须**同一次提交**进 `zh-CN.ts` 与 `en.ts` |
| `menu:check` | 退出码 0 | 本项不动菜单 |
| `perms:check` | 退出码 0，63 码 | 本项**不新增权限码**、不改 `canManage` |
| `ui:check` | 退出码 0，**白名单冻结读数不增** | R6（裸 `aria-label`）与 R7（孤儿组件）——见下 |
| `test:coverage` | 四项 ≥ **33.6 / 47.2 / 21.4 / 33.6** | 新 hook 与新组件进 `functions` 分母 |

**`ui:check` 的三条具体约束**（读失败信息时对着看）：

- **R6**：本项**新增** `aria-label` ⇒ 必须写成 `aria-label={t('…')}`。写成裸字面量会让白名单台账被迫增长，而该台账是**冻结**的——`ui:check` 双向校验，增加即红。
- **R7**：`components/ui/Highlight.tsx` 靠 **barrel 再导出**算被引用；`components/DepartmentDetail.tsx` 靠**页面 import**算被引用。两者都不是孤儿。
- **R1**：高亮的色值 `#ffe58f` **不在** `BRAND_COLORS` 词表内 ⇒ 提取与布线都不触发。

**覆盖率读数怎么读**：与**阈值**比，**不**与上一次运行的小数位比（`vite.config.ts` 明文禁止引用单次运行的小数位当论据），**不**下调阈值（故 `specs/083-engineering-consolidation/data-model.md` §4 无需同步）。

## 2. 定向破坏（判据的**可证伪性**，不是「新增 N 条用例全绿」）

「用例全绿」不构成证据——**用例可能根本没跑到它声称的场景**（本仓有先例）。故本项每一条声称是护栏的断言，都要被观测到**在破坏下转红**：

| # | 破坏 | 应红在哪 |
|---|---|---|
| 1 | 把 `<Highlight …/>` 换回裸 `{node.name}` | 高亮断言（`<mark>` 计数） |
| 2 | 去掉 `useDebouncedValue`、直连 `searchValue` | 防抖断言（窗口内不重算） |
| 3 | 删掉 `<PageState state="empty" />` | 空态断言（`page-state-empty` 在场） |
| 4 | 把 `isMobile` 写死 `true` | **桌面分支**断言（Modal 那条） |
| 5 | 删掉搜索框的 `aria-label` | aria 断言 |

纪律：**逐个做、逐个逐字节还原**，破坏期间**不提交**。每次还原后核对生产代码**逐字节**回原样（`git diff` 为空）。逐字失败信息写入 `falsification-evidence.md` 的 §B–§F。

> **第 4 条是本项最重的一条**：`src/test/setup.ts` 把 `matchMedia` **恒桩成 `matches: false`** ⇒ `Grid.useBreakpoint().lg` 恒假 ⇒ `isMobile` **恒真** ⇒ **桌面分支在默认桩下永远不执行**。因此桌面分支的用例**必须在该测试文件内覆盖 `matchMedia`**（范式见 `pages/map/UsageMapPage.test.tsx`），并留注释说明「全局桩未改、只有本文件覆盖」。把 `isMobile` 写死 `true` 仍必须让桌面那条转红——否则它证明不了自己跑过。

## 3. 手工冒烟（`pnpm dev` + 后端在跑，用 `admin / admin123`）

| # | 操作 | 期望 |
|---|---|---|
| 1 | 部门页搜索框输入「华东」 | 节点标题里「华东」被 `<mark>` 标出（浅黄底 `#ffe58f`）；过滤在**停止输入约 300ms 后**才发生 |
| 2 | 清空搜索框 | 树**展开全部**（这是本项**有意的可见行为变化**，见下） |
| 3 | 输入一个不存在部门名 | 显示**空状态**（「暂无数据」），不是一片空白 |

| 5 | DevTools 切到 375px（窄屏），打开详情 | 走**底部抽屉**；切回宽屏（≥992px）走**对话框** |
| 6 | Tab 键遍历本页 | 搜索框与树可被聚焦；搜索框与树容器有可朗读名称 |

> ⚠️ **第 2 条与第 5 条是可见变化**，须落到使用者的目视确认，见 `spec.md` 的 SC-095-006。本项**未获视觉背书**。

## 4. 本项**不声称**验证过的事（口径边界，先立规矩）

| 不声称 | 为什么 |
|---|---|
| 窄屏抽屉的**真实排版**、方向键的**真实行为** | 测试环境（jsdom）**没有布局引擎**，也**没有真实焦点模型** ⇒ 本项断到的是**结构与配置值**，只记作「结构前提已断言」 |
| 「防抖窗口内没有重算」在**页面层**的量 | 该读数**只在 `useDebouncedValue` 自己的单测里**量（`vi.useFakeTimers()`）；页面层只量「最终结果与不防抖时一致」（页面级 fake timers 会与 antd 内部定时器缠死） |
| 宽屏/窄屏的 **e2e 几何回归** | 属 092，本项**不新增 e2e** |
| 视觉观感是否令人满意 | 见上，**未获视觉背书**，如实记为欠账 |

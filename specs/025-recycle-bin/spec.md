# Feature Specification: 回收站与批量恢复

**Feature Branch**: `025-recycle-bin`

**Created**: 2026-08-23

**Status**: Draft

**Input**: User description: "回收站与批量恢复：统一管理逻辑删除的客户/线索/联系人/商机等数据，支持查看、批量恢复与彻底删除"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 回收站列表 (Priority: P1)

管理员（或按数据权限）在"回收站"页面查看所有已逻辑删除的数据（客户/线索/联系人/商机/销售机会等），按实体类型分类，展示删除时间与删除人，可搜索。

**Why this priority**: 系统数据均为逻辑删除（deleted=1），但当前无统一管理入口，误删数据无法找回。回收站让删除可见、可查、可恢复，是数据安全闭环。

**Independent Test**: 可独立验证——删除一个客户后，回收站中按"客户"分类可见该记录及其删除时间。

**Acceptance Scenarios**:

1. **Given** 用户删除了一条客户记录，**When** 打开回收站，**Then** 该记录出现在"客户"分类，显示名称与删除时间。
2. **Given** 回收站有多个实体的删除记录，**When** 按实体类型筛选，**Then** 仅显示对应类型。
3. **Given** 回收站记录较多，**When** 输入关键字搜索，**Then** 仅显示匹配记录。

### User Story 2 - 批量恢复 (Priority: P1)

管理员可从回收站选择多条记录批量恢复（deleted=0），恢复后数据回到原列表，关联关系（如客户下的联系人）不受影响。

**Why this priority**: 批量恢复是回收站的核心操作，减少逐条恢复成本；恢复后数据立即可用。

**Independent Test**: 可独立验证——恢复一条已删除的客户后，客户列表重新出现该客户。

**Acceptance Scenarios**:

1. **Given** 回收站有多条删除记录，**When** 勾选并点击"恢复"，**Then** 记录从回收站消失，回到原列表。
2. **Given** 恢复的客户原本有联系人/商机关联，**When** 恢复后查看详情，**Then** 关联数据仍存在。

### User Story 3 - 彻底删除（可选） (Priority: P2)

管理员可从回收站彻底删除（物理删除）记录，彻底删除后不可恢复。

**Why this priority**: 回收站记录长期积累占用空间，且部分数据确需彻底清除（隐私/合规）。

**Independent Test**: 可独立验证——彻底删除一条记录后，回收站与列表中均不再出现。

**Acceptance Scenarios**:

1. **Given** 回收站有一条记录，**When** 点击"彻底删除"并确认，**Then** 记录物理删除，不可恢复。

### Edge Cases

- 数据权限：SALES 用户仅能看到自己删除的记录；ADMIN 全量。
- 恢复时唯一性冲突（如恢复的客户名称与现有客户重复）：提示冲突，该条恢复失败。
- 彻底删除的实体有关联数据（如客户有订单）：按各实体策略处理（提示或级联）。
- 空回收站：显示空状态。
- 回收站查询不触发 MyBatis-Plus 逻辑删除过滤（需显式查 deleted=1）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须提供回收站列表，按实体类型（客户/线索/联系人/商机/销售机会/合同/订单/工单）展示已逻辑删除记录，含名称/删除时间/删除人，支持类型筛选与关键字搜索。
- **FR-002**: 系统必须支持单条与批量恢复（deleted=0），恢复后数据回到原列表且关联关系保留。
- **FR-003**: 系统必须支持彻底删除（物理删除），删除后不可恢复。
- **FR-004**: 回收站访问必须遵循数据权限：SALES 仅本人删除的记录，ADMIN 全量。
- **FR-005**: 恢复时遇到唯一性冲突必须提示并跳过该条（其余继续）。
- **FR-006**: 删除与恢复必须记录审计日志。

### Key Entities

- **回收站条目（RecycleItem）**: 派生视图（实体类型、id、名称、删除时间、删除人），跨实体查询 deleted=1 记录。
- **恢复/彻底删除操作**: 按实体类型分发到对应 Mapper（update deleted=0 或物理 delete）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 回收站列表正确率 100%——删除 5 条不同实体记录后，回收站准确展示（抽查 10 次）。
- **SC-002**: 恢复正确率 100%——恢复后记录回到原列表、关联数据保留（抽查 10 次）。
- **SC-003**: 彻底删除正确率 100%——删除后回收站与列表均不再出现（抽查 5 次）。
- **SC-004**: 唯一性冲突处理正确率 100%——冲突条恢复失败并提示，其余成功。
- **SC-005**: 数据权限隔离正确率 100%——SALES 仅见本人删除记录。

## Assumptions

- 回收站覆盖核心实体：客户、线索、联系人、商机、销售机会、合同、订单、工单（各实体 Mapper 均继承逻辑删除）。
- 恢复 = update deleted=0（MyBatis-Plus 逻辑删除逆向）；彻底删除 = 物理 delete（绕过逻辑删除）。
- 恢复唯一性冲突仅针对有唯一约束的实体（客户名称+公司、线索、产品编码等）。
- 关联数据策略：恢复不动关联（关联数据若也被删除需一并恢复）；彻底删除按实体已有约束处理。
- 回收站仅 ADMIN 可见全部，SALES 仅本人（如系统无 SALES 删除权限则回收站基本为 ADMIN 功能）。

# Feature Specification: 智能线索评分与销售预测校准

**Feature Branch**: `019-lead-scoring`

**Created**: 2026-08-23

**Status**: Draft

**Input**: User description: "智能线索评分与销售预测校准：按来源/公司规模/跟进活跃度等规则自动打分排序线索，用历史转化率校准销售预测概率"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 线索自动评分 (Priority: P1)

系统根据线索的来源渠道、公司信息完整度、跟进活跃度、最近互动等规则，自动计算 0-100 的线索评分（无需销售手工填写）。线索列表与线索池按评分排序，销售优先处理高分线索。

**Why this priority**: 线索当前有 `score` 字段但需手工填写，多数线索为 0 分，无法辅助排序。自动评分把"该先打哪个电话"的决策标准化，是线索池利用效率的关键。

**Independent Test**: 可独立验证——创建一条来自高质量来源、信息完整且有跟进记录的线索，评分应显著高于来源普通、信息不全、无跟进的线索。

**Acceptance Scenarios**:

1. **Given** 一条新线索（来源=REFERRAL 推荐、公司/职位/电话/邮箱齐全），**When** 创建或查看线索列表，**Then** 系统自动给出 ≥60 的评分（绿色）。
2. **Given** 一条线索仅有姓名与电话且来源为 COLD_CALL，**When** 创建，**Then** 评分较低（<40，红色）。
3. **Given** 销售对线索进行了跟进，**When** 跟进后查看线索，**Then** 评分因"跟进活跃度"维度上升。
4. **Given** 线索有手工评分（历史数据），**When** 系统重新自动评分，**Then** 以自动评分为准（自动评分覆盖手工值）。

### User Story 2 - 销售预测校准 (Priority: P2)

系统根据历史销售机会的真实转化数据，统计各阶段的转化率，替换当前硬编码的概率（20%/50%），用于销售预测的加权计算，使预测更接近实际。

**Why this priority**: 当前预测用固定概率（INITIAL_CONTACT=0.2、NEGOTIATING=0.5），与真实转化情况可能有偏差。用历史数据校准后，加权预测金额更可信。

**Independent Test**: 可独立验证——在有一定历史机会数据的系统中，预测接口返回的各阶段概率与按历史数据计算的转化率一致。

**Acceptance Scenarios**:

1. **Given** 系统有足够历史机会（如 100 条），**When** 计算销售预测，**Then** 各阶段概率使用历史转化率（如 INITIAL_CONTACT 阶段 50 条中 20 条进入下一阶段 → 概率 0.4），而非固定 0.2。
2. **Given** 历史数据不足（如某阶段样本 < 10），**When** 计算预测，**Then** 该阶段回退到默认概率并标注"样本不足"。
3. **Given** 管理员查看预测接口，**When** 响应返回，**Then** 包含各阶段的概率来源说明（历史计算 or 默认回退）。

### User Story 3 - 评分规则配置 (Priority: P3)

管理员可以配置线索评分各维度（来源渠道、信息完整度、跟进活跃度）的权重与分值，配置后立即生效。

**Why this priority**: 不同业务的线索质量判断标准不同，可配置性让评分规则可调整，避免硬编码。

**Independent Test**: 可独立验证——调整某维度权重后，线索评分随之变化。

**Acceptance Scenarios**:

1. **Given** 管理员调整"来源渠道"维度分值，**When** 重新计算线索评分，**Then** 评分按新配置计算。
2. **Given** 配置的维度权重合计不等于 100，**When** 保存配置，**Then** 提示校验错误或自动归一化。

### Edge Cases

- 线索无任何评分输入信息（仅姓名）时，给基础分（如 30）。
- 评分维度依赖数据（跟进记录）为空时，该维度按 0 分处理。
- 历史转化率计算时，某阶段样本不足（<10）回退默认概率。
- 预测校准不改变赢单机会（CLOSED_WON=1.0、CLOSED_LOST=0.0）的固定语义。
- 自动评分不应覆盖销售明确标记的"已转化/已放弃"状态。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须自动计算线索评分（0-100），维度包括来源渠道、信息完整度、跟进活跃度、互动时效，规则可配置。
- **FR-002**: 线索创建与更新时自动评分，评分结果存储到线索的 score 字段并随列表/详情返回。
- **FR-003**: 线索列表与线索池必须支持按评分排序（默认降序），并用红/黄/绿标识分数区间（可配置阈值，默认 <40 红、40-69 黄、≥70 绿）。
- **FR-004**: 跟进记录新增后，线索评分必须重新计算（跟进活跃度维度生效）。
- **FR-005**: 系统必须根据历史销售机会数据统计各阶段转化率（从本阶段进入下一阶段的比例），用于销售预测加权。
- **FR-006**: 某阶段历史样本不足（<10 条）时，预测回退到默认概率，并在响应中标注概率来源。
- **FR-007**: 评分规则（维度权重/分值/阈值）必须支持管理员配置，配置后立即生效。
- **FR-008**: 销售预测接口必须返回各阶段概率及其来源（HISTORICAL / DEFAULT）。

### Key Entities

- **线索评分规则（LeadScoreRule）**: 配置项（来源渠道分值、信息完整度分值、跟进活跃度分值、颜色阈值），存配置表或配置文件。
- **阶段转化率（StageConversionRate）**: 派生指标，由历史销售机会统计得出（阶段 → 转化率 + 样本数），随预测计算，不持久化（或短缓存）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 线索评分正确率 100%——对 20 条人工标注的高/中/低质量线索，规则评分与人工判断一致。
- **SC-002**: 自动评分覆盖全部线索：系统中 100% 线索有非空评分（原为 0 分的手工缺省值被覆盖）。
- **SC-003**: 预测概率校准正确：对历史样本充足的阶段，计算概率与人工核算一致（抽查 10 次）。
- **SC-004**: 样本不足回退正确率 100%：样本 <10 的阶段全部回退默认概率并标注来源。
- **SC-005**: 评分规则配置变更后下一个查询周期（≤1 分钟）内生效。

## Assumptions

- 线索评分采用规则引擎（可配置分值表），非机器学习模型。
- 评分实时计算并写回线索 score 字段（创建/更新/跟进后触发），保证列表排序可直接用 score。
- 阶段转化率基于历史 CLOSED_WON 与各阶段进入量的统计（简化为：某阶段转化率 = 该阶段流向下一阶段或赢单的数量 / 该阶段总量），按需用 Redis 短缓存。
- 预测校准不引入新依赖；CLOSED_WON/CLOSED_LOST 概率固定 1.0/0.0 不参与校准。
- 评分/预测规则配置沿用现有配置模式（health_score_config 同款表结构或配置文件）。

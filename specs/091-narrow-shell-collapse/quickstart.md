## 一、几何实测（SC-001~004）——本项的主要判据

```bash
cd specs/091-narrow-shell-collapse
node measure-narrow-shell.mjs
# 想换地址：CRM_BASE=http://localhost:5174 node measure-narrow-shell.mjs
```

脚本**只读**：只打 dev server，不写库、不改代码。

**要看的两段输出**：

### 窄屏段（320 / 375 / 414 / 767）

采样页：`/stats`、`/customers`、`/orders`、`/roles`。

| 观测量 | 期望 | 缺陷态（改动前） |
|---|---|---|
| **内容区可见宽度**（`.page-scroll` 的 `clientWidth`，含内边距） | 分别 **320 / 375 / 414 / 767**（＝视口宽） | 恒 **24** |
| **内容容器宽度**（`.page-container` 内容盒） | 分别 **296 / 351 / 390 / 743**（＝视口宽 − 自身左右内边距各 12） | 恒 **0** |
| 菜单容器 | 宽＝**视口宽**（＝内容区可见宽，**不是** 351），高＝**48** | **200×200** |
| 页面级横向溢出 | **0** | 0（缺陷态也没有，故这一项是**防新增**） |

> **⚠️ 前两行是两个不同的量，不得互换、不得只报其一。** 判据（SC-001）原本把它们混为一句
> （「改动前 24」量的是内容区，「应达 351」量的是内容容器），照原口径写门禁会量错元素、
> 把已修复的状态判成「不达标」。订正留痕见 `spec.md` 的「订正块」。
> 简记：**内容区可见宽 ＝ 视口宽；内容容器宽 ＝ 视口宽 − 24。**

> **注意**：内容区**实际内容宽**在窄屏仍会大于可见宽（表格要横向滚动），这是**预期的**，
> 不构成本项失败——本项只要求「内容区本身可见」，不要求「表格不横向滚动」（spec 非目标第 1 条）。
> 同理，**菜单条是溢出折叠（`...`），不是横向滚动**：实测 `scrollWidth == clientWidth == 375`，
> 没有可滚动余量。

### 宽屏段（768 / 1024 / 1280 / 1440 / 1920）

与**改动前**逐项比对侧边栏宽度、内容区上下左右边界、页脚位置。**必须逐项相同**。
（改动前的一组可比对读数：768 → 内容容器 520；1024 → 776。脚本会打印同口径的值。）

### 跨断点切换（必测，research.md §7 第 1 条）

从 1024 拖到 375，再拖回 1024：

1. 窄屏下那条「含侧边栏」的类名**始终不出现**；
2. 拖回宽屏后它**重新出现**，侧边栏可见；
3. 回宽屏后的几何与**初始**逐项相同（不残留窄屏的内联样式）。

## 二、判据会红（SC-006）——**不能省的一步**

```bash
cd frontend
npx vitest run src/App.render.test.tsx
```

留痕三次输出：

1. **修复态** → 新用例通过；
2. **把窄屏外壳改回旧写法**（窄屏照样按「含侧边栏的布局」渲染）→ 新用例**失败**；
3. **还原** → 通过。

**为什么这一步不能省**：本仓有过「用例是绿的，而它声称的场景根本没执行」的先例（research.md §4）。
只报「新增 N 条用例、全绿」**不构成证据**——必须看到定向破坏真的让它红了。

## 四、肉眼核对（截图清单）

窄屏 **375** 与宽屏 **1440** 各一组，逐页看：

| 页面 | 看什么 |
|---|---|
| `/customers` | 菜单条是**整宽一条**（不是左上角方块）；内容区满宽；表格/筛选可见可点 |
| `/tags` | 表格在页签里，页签与内容都满宽 |

| 任一页面（宽屏） | **看不出任何变化** |

## 五、明确**不算**本项失败的现象

- 窄屏下表格仍需横向滚动、表单仍可能拥挤、统计卡仍可能折行 —— 这些是**页面级**问题，
  属 spec 非目标第 1 条，需另立一项。
- 窄屏下菜单条内部的分隔线/折叠指示的观感细节（本轮只做过截图核对，未逐项量）。

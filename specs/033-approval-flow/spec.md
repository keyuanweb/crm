# Feature Specification: 通用多级审批流

**Feature Branch**: `033-approval-flow`

**Created**: 2026-08-23

**Status**: Draft

**Input**: P0-二批：可配置多级条件审批，替代合同/报价单现有单级审批（业界泛微/致远/飞书审批标配）。

## User Stories

### US1 - 审批流配置 (P1)
管理员可配置审批流（按业务类型：合同/报价单/其他）：节点序列（审批人角色/指定人/发起人上级）、条件分支（如金额>10万 走多一级）、超时提醒；启用后应用于对应业务提交。

**验收**: 配置"合同审批流"：金额≤10万 单级（销售经理）、>10万 双级（+总经理）→ 提交合同按规则流转。

### US2 - 审批执行 (P1)
业务提交审批后进入审批流；审批人收到通知（复用 026 实时通知）→ 通过/驳回/转交 → 多级逐级流转；审批记录（谁/何时/意见/结果）可追溯；驳回退回发起人修改重提。

**验收**: 双级审批：一级通过 → 自动到二级 → 二级驳回 → 退回发起人 → 修改重提 → 重新走流程。

## Requirements

- **FR-001**: 审批流定义 CRUD：业务类型/节点列表/条件分支（基于金额等字段）/启用状态。
- **FR-002**: 提交审批：业务（合同/报价）提交时匹配启用审批流，生成审批实例（approval_instance + approval_task）。
- **FR-003**: 审批执行：当前节点审批人通过/驳回/转交；通过推进下一节点，驳回退回发起人。
- **FR-004**: 审批记录：实例维度完整日志（节点/审批人/意见/时间/结果）。
- **FR-005**: 通知：新审批任务推送给审批人（WebSocket + 通知中心），超时提醒（可选）。
- **FR-006**: 兼容：未配置审批流的业务走原逻辑；已生效合同/报价审批迁移到新引擎。
- **FR-007**: 权限：审批流配置为系统管理权限（workflow:manage）；审批人由流程定义确定。

## Success Criteria

- SC-001: 审批流配置正确率 100%（多级+条件分支抽查 5 配置）。
- SC-002: 双级审批流转正确率 100%（通过→通过→驳回→重提全流程抽查 5 次）。
- SC-003: 审批记录完整率 100%（日志无缺失抽查 5 实例）。
- SC-004: 通知送达率 100%（审批人收到实时通知）。
- SC-005: 既有合同/报价单级审批无回归（存量测试通过）。

## Edge Cases

- 审批人离职/停用：节点自动跳过或转交（配置兜底）。
- 并发审批：同一实例仅一个审批人可操作（状态机校验）。
- 条件分支金额边界：等于阈值归属（配置说明）。
- 审批中业务被删除：实例标记取消。

## Assumptions

- 通用审批引擎独立于业务（approval_instance/approval_task/approval_log 表）；合同/报价通过接口接入。
- 审批人支持角色/指定人/发起人上级三种类型。
- 条件分支先支持金额字段，后续可扩展（配置化条件表达式）。
- 复用 026 实时通知 + 017 工作流基础。

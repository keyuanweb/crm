# 功能规格：前端体验优化模块

**功能分支**: `039-dashboard-ux`

**创建日期**: 2026-08-24

**状态**: 草稿

**输入**: 用户反馈的前端体验问题：1）点击菜单切换页面时"整个页面闪一下"——懒加载页面 chunk 首次加载时 Suspense fallback（居中 Spin）造成内容区闪烁；2）首页【客户分析】卡片布局错乱——卡片被 flex 拉伸留白、统计项三列在窄屏挤压。需要路由切换无闪烁、首页卡片布局稳定。

## 用户场景与测试（必填）

### 用户故事 1 - 菜单切换无闪烁（优先级：P0）

用户点击左侧菜单在任意页面间切换时，内容区应直接呈现目标页面，不应出现先空白/转圈再显示的闪烁。

**优先级理由**: 页面切换闪烁是最直观的体验问题，影响所有页面的日常使用，P0 最先交付。

**独立测试**: 登录后点击多个菜单项，内容区无空白/转圈闪现。

**验收场景**:

1. **Given** 用户已登录，**When** 点击任意菜单项切换页面，**Then** 内容区直接显示目标页面，无居中 Spin 或空白闪现。
2. **Given** 用户首次登录（页面 chunk 尚未加载），**When** 点击菜单，**Then** 短暂骨架占位后显示页面，且布局高度不塌陷跳动。
3. **Given** 用户在窄屏（<768px）使用，**When** 切换页面，**Then** 同样无闪烁且布局稳定。

---

### 用户故事 2 - 首页客户分析卡片布局稳定（优先级：P0）

首页"客户分析"卡片在桌面与窄屏下均布局整齐：统计项不挤压、卡片不被拉伸留白。

**优先级理由**: 首页是登录后的第一屏，卡片错乱直接影响第一印象，与故事 1 同批交付。

**独立测试**: 桌面与窄屏下查看首页客户分析卡，三统计项排列整齐。

**验收场景**:

1. **Given** 桌面宽度（≥992px），**When** 查看首页客户分析卡，**Then** 三个统计项（客户总数/活跃客户/本月新增）横排整齐，卡片高度与内容匹配、无大块留白。
2. **Given** 窄屏（<768px），**When** 查看同一卡片，**Then** 统计项垂直堆叠、不挤压换行。
3. **Given** 首页左侧列存在公告卡，**When** 滚动查看，**Then** 跟进活动卡与公告卡高度自适应、无错位。

### 边界情况

- 页面 chunk 首次加载失败（网络抖动）：点击菜单回退到按需加载，不白屏。
- 公告为空时公告卡不占位过高，跟进活动卡正常填充。
- 移动端（<768px）菜单切换同样生效。

## 需求（必填）

### 功能需求

#### 菜单切换无闪烁

- **FR-UX01**: 登录后必须预加载全部懒加载页面 chunk，使菜单切换时目标页已缓存。
- **FR-UX02**: 页面切换必须使用 React 并发过渡（startTransition），Suspense 挂起期间保持旧 UI 而非显示 fallback。
- **FR-UX03**: Suspense fallback 必须为与内容区同高的骨架占位（兜底），不得为居中 Spin 造成布局跳动。

#### 首页客户分析卡片

- **FR-UX04**: "客户分析"卡片必须取消 flex 拉伸，采用自然高度，避免内容少时顶部留白。
- **FR-UX05**: 卡片内统计项必须为响应式栅格（窄屏垂直堆叠，宽屏横排）。
- **FR-UX06**: 首页左侧列（客户分析/跟进活动/团队公告）高度必须自适应均衡。

### 关键实体（涉及数据）

- 无新增实体。纯前端展示与交互优化，涉及文件：
  - `frontend/src/App.tsx`（路由预加载、startTransition、Suspense fallback）
  - `frontend/src/pages/stats/DashboardPage.tsx`（客户分析卡片布局）
  - `frontend/src/components/AnnouncementCard.tsx`（公告卡弹性填充）

## 成功标准（必填）

### 可度量结果

- **SC-UX01**: 预加载完成后（登录后 ≤5 秒），点击任意菜单项切换到目标页无可见空白/转圈（人工抽查 10 次切换，0 次闪烁）。
- **SC-UX02**: 客户分析卡在桌面与窄屏（375px）下统计项无挤压换行（抽查 2 个宽度）。
- **SC-UX03**: 前端 typecheck / lint / build 全部通过，无回归。

## 假设

- 页面 chunk 数量约 51 个，预加载在登录后立即触发，带宽消耗可接受（局域网/常规网络环境）。
- 预加载失败不影响主流程（点击时仍按需加载兜底）。
- 本模块为纯前端优化，无后端/契约/迁移变更。

# Feature Specification: 登录验证码

**Feature Branch**: `017-login-captcha`

**Created**: 2026-08-23

**Status**: Draft

**Input**: User description: "登录页面新增验证码，根据sdd规范新增需求"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 登录前输入图形验证码 (Priority: P1)

用户打开登录页时，系统显示一个图形验证码。用户输入用户名、密码和验证码后提交登录。验证码正确且凭证有效则登录成功；验证码错误则拒绝登录并提示，同时刷新验证码供重试。

**Why this priority**: 这是验证码功能的核心价值——在登录入口增加一道人机校验，防止自动化脚本暴力破解账号，是所有后续增强的前提。

**Independent Test**: 可在登录页独立验证——输入正确验证码 + 正确凭证可登录，输入错误验证码被拒绝且验证码自动刷新。

**Acceptance Scenarios**:

1. **Given** 用户处于登录页，**When** 页面加载完成，**Then** 显示一个可识别的图形验证码及其输入框。
2. **Given** 用户输入了正确的用户名、密码和验证码，**When** 提交登录，**Then** 登录成功并进入系统首页。
3. **Given** 用户输入了正确的用户名、密码但验证码错误，**When** 提交登录，**Then** 登录被拒绝，提示"验证码错误"，验证码自动刷新，用户名与密码输入框内容保留。
4. **Given** 用户输入了正确的用户名、密码但验证码为空，**When** 提交登录，**Then** 前端提示"请输入验证码"，不发起登录请求。

### User Story 2 - 刷新验证码 (Priority: P2)

当验证码看不清、已过期或输入错误后，用户可以点击验证码图片刷新，获取一个新的验证码，无需重新加载整页。

**Why this priority**: 提升可用性——验证码可能因干扰线/字符形似而难以辨认，用户需要便捷的刷新途径，避免因验证码不可读而阻塞登录。

**Independent Test**: 可独立验证——点击验证码图片后，图片内容（或验证码标识）发生变化，旧验证码失效。

**Acceptance Scenarios**:

1. **Given** 用户处于登录页，**When** 点击验证码图片，**Then** 验证码图片更新为新内容，输入框清空。
2. **Given** 验证码已过期，**When** 用户提交登录，**Then** 提示"验证码已过期，请重新输入"，验证码自动刷新。

### User Story 3 - 验证码一次性失效（防重放） (Priority: P2)

同一个验证码被提交校验后立即失效，即使校验通过或失败，都不能再次使用，防止攻击者捕获验证码后重放。

**Why this priority**: 安全关键——保证验证码只能使用一次，避免被自动化工具重复提交同一答案绕过校验。

**Independent Test**: 可独立验证——使用同一验证码连续提交两次，第二次必被拒绝。

**Acceptance Scenarios**:

1. **Given** 某验证码已被提交校验（无论结果），**When** 使用同一验证码再次提交，**Then** 被拒绝并提示验证码错误或过期。

### Edge Cases

- 验证码过期时间边界：刚好过期时提交应被拒绝。
- 验证码区分大小写？——采用不区分大小写的字母数字组合，降低输入难度。
- 并发刷新：用户快速连续点击刷新，仅最后一次生成的验证码有效。
- 登录失败次数与验证码的关系：无论失败次数多少，登录始终要求验证码（不因失败次数动态开关，保持行为一致）。
- 验证码图片加载失败：显示占位并允许点击重试。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须在登录页显示图形验证码，包含 4~6 位字母数字组合（不区分大小写，排除易混淆字符如 0/O/1/I/l）。
- **FR-002**: 系统必须提供获取验证码的能力：每次获取生成唯一标识与对应答案，答案仅在服务端保存。
- **FR-003**: 系统必须在登录请求中校验验证码：验证码错误、为空、已过期或已使用均拒绝登录，并返回明确错误提示。
- **FR-004**: 验证码必须有有效期（默认 5 分钟），过期后校验失败。
- **FR-005**: 验证码必须一次性使用：提交校验后立即失效，无论校验结果如何。
- **FR-006**: 用户必须能够通过点击验证码图片刷新获取新验证码，旧验证码随之失效。
- **FR-007**: 验证码校验必须先于或独立于凭证校验，且验证码错误不触发凭证错误计数（不因验证码错而累计登录失败次数）。
- **FR-008**: 系统必须记录验证码生成与校验失败的日志（结构化日志），用于安全审计。
- **FR-009**: 登录失败时（凭证错误或验证码错误），前端保留用户名输入，验证码自动刷新并清空。

### Key Entities

- **验证码会话（Captcha Session）**: 表示一次验证码的生命周期；包含唯一标识、答案、创建时间、过期时间、是否已使用。仅在服务端临时保存，过期即清理，不持久化到数据库。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 验证码校验正确率 100%（抽查 20 次正确输入全部通过，20 次错误输入全部被拒绝）。
- **SC-002**: 验证码从获取到页面可见的渲染时间在 1 秒内。
- **SC-003**: 验证码一次性失效生效：同一验证码重复提交的拒绝率 100%。
- **SC-004**: 验证码过期失效生效：超过有效期的验证码提交被拒绝率 100%。
- **SC-005**: 合法用户（正确验证码 + 正确凭证）登录成功率 100%，无因验证码导致的误拦截。

## Assumptions

- 验证码采用图形验证码（服务端生成图片），非短信/邮件验证码，也非第三方滑块验证码。
- 验证码答案临时存储在服务端缓存（复用现有 Redis），不写入数据库。
- 验证码为字母数字组合（不区分大小写），不含易混淆字符，避免数学题或滑块形式。
- 登录流程复用现有认证服务；验证码作为登录前置校验叠加，不改变令牌签发逻辑。
- 现有登录失败锁定（5 次锁 15 分钟）保持不变；验证码错误不参与失败计数。

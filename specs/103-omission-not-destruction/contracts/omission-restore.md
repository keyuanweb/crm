# 契约：自定义字段受保护值的回补（103）

**Type**：实现行为契约（**无端点变更、无请求/响应结构变更**；变更的是**保存路径的补偿行为**）

**Base**：`/api/v1/custom-fields` 及其在四个实体保存路径上的副作用（`CustomFieldService.saveValues`）

**由本文件说明的约定**：`specs/056-field-permission/contracts/field-permission.md` 的「保存拦截」一节（**该文件一字未改**，其原文逐字收存于本文 §2）

---

## 1 为什么这份契约存在 —— **方向必须读准**

按章程**原则一（契约优先的 API 设计，不可协商）**——「契约不得被静默修改，任何偏差必须明确说明理由并登记」（`.specify/memory/constitution.md:21`、`:78`）——行为的变更需要一个登记位置。

**但本项的情形与 101 不同，不得混用**。三个方向并列如下：

| | 085（`GlobalExceptionHandler` 的注释即判例） | 101（`062`） | **103（本项）** |
|---|---|---|---|
| 情形 | `FormService` 在限流时抛 400，而 `036` 的契约承诺 **429** | `062` 的契约承诺「模拟同步、Response 200、`syncStatus: SYNCED`」，而这条行为**本身就是不实的** | 056 的契约**对「省略 / 回补」没有任何约定** |
| 谁对 | **契约对**，实现错 | **契约写下了不实的行为** | **契约没写**——它只写了「客户端提交时」的两条拦截，**没写客户端省略时**该怎样 |
| 处置 | 契约一个字符不改，**改实现** | 062 **仍一字不改**，变更登记写在 101 自己的契约里 | 056 **一字不改**，登记写在**本文**；103 补的是契约**射程之外**的那半边 |
| 性质 | **违反**契约 | **偏离**契约 | **实现侧缺口**，**不是**对一纸承诺的偏离 |

⚠️ **一处必须纠正的上游表述**：`specs/102-builtin-field-permission/spec.md:194`（非目标 3）与 `research.md:206` 都把自定义字段 READ_ONLY 的省略缺陷称为「**056 契约覆盖的行为**」。**这个理由过宽**——056 的契约并不覆盖补偿行为。**其结论（应当登记）成立，其理由不成立。**

⇒ 103 **不得复述 102 的理由**。准确分类见下行：

> **「省略即销毁」落在 056 契约的射程之外**——契约的两条都要求**客户端先提交**（提交 HIDDEN ⇒ 422；改 READ_ONLY ⇒ 422），而**省略侧没有条款**。103 补的是这半边，并在本文里**逐字收存** 056 的两条原文（§2）与变更对照（§3）。

101 的先例**只在形式上可迁移**（台账放**新批自己的** `contracts/` 里、**旧 spec 目录一字不动**、对其 `git diff` **必须为零**），**理由不同**。

## 2 被说明的原文（**逐字保留，可 grep**）

### 2.1 056 的保存拦截约定（`specs/056-field-permission/contracts/field-permission.md:41-44`）

> ### 保存拦截（CustomFieldService.saveValues）
>
> - 提交 HIDDEN 字段值 → 422 `FIELD_HIDDEN`。
> - 提交 READ_ONLY 字段（修改已有值）→ 422 `FIELD_READ_ONLY`。

### 2.2 056 的字段列表响应扩展（同文件 `:31-39`，**逐字**）

> ### GET /api/v1/custom-fields?entityType=CUSTOMER（扩展）
>
> 字段列表响应每项增加：
>
> ```json
> "permission": { "hidden": false, "readOnly": true }
> ```
>
> （基于当前登录角色计算；ADMIN 恒 editable。）

### 2.3 056 的错误码表（同文件 `:48-53`，**逐字**）

> | code | status | 含义 |
> |---|---|---|
> | FIELD_PERMISSION_INVALID | 422 | 权限值不合法（须 HIDDEN/READ_ONLY/EDITABLE） |
> | FIELD_HIDDEN | 422 | 该字段对当前角色隐藏，不可写入 |
> | FIELD_READ_ONLY | 422 | 该字段对当前角色只读，不可修改 |
> | FIELD_PERMISSION_NOT_FOUND | 404 | 权限配置不存在 |

### 2.4 056 对「省略」零覆盖的判据（**可 grep 复核**）

`specs/056-field-permission/**` 全目录 grep `省略|回补|恢复|restore|部分更新|子集` ⇒ **零命中**（实测）。

实现里**有**政策表述（`backend/src/main/java/com/crm/service/CustomFieldService.java:252-253` 的「看不见不等于该被删除」），但那是**实现注释**，**契约层没有对应条款**。

## 3 变更对照

| 维度 | 056 原约定（§2 逐字） | 103 实现 | 不变的部分 |
|---|---|---|---|
| 提交 HIDDEN 自定义字段 | 422 `FIELD_HIDDEN` | **不变** | 码、状态码、判定 |
| 提交 READ_ONLY 字段且**值与库中不同** | 422 `FIELD_READ_ONLY` | **不变** | 判据 `existing == null \|\| !existing.equals(value)` |
| 提交 READ_ONLY 字段且**原样回传** | 契约未写（实现放行） | **不变**（且现在有 U3/I2 钉着它**不产生重复行**） | 放行 |
| **省略** READ_ONLY 字段 | **056 未作任何约定**（§2.4 grep 零命中） | **按库中原值回补** | —— |
| **省略** HIDDEN 字段 | （同上：未作约定） | **不变**（102 已回补；本批仅把谓词从 `hidden` 扩为 `!EDITABLE`） | 回补行为本身 |
| **省略** EDITABLE 字段 | 未作约定 | **仍是删除**（**刻意**） | —— |
| 字段列表响应含 `permission` 标记 | （§2.2） | **不变**（本批只在**前端**消费它） | 形状、语义 |
| 错误码 | （§2.3） | **不变** | 四个码 |

**「不变的部分」列是本表的重点**：本批**不动**任何已写下的 056 语义；它只在**契约未写的省略侧**补上补偿行为。⇒ **056 的实现与其契约保持一致**，差异**全部落在契约的空白处**。

## 4 本批**不**承诺的部分（避免读者过度外推）

1. **不承诺**「省略即保留」是一条**普适**规则：它只对**受保护**（HIDDEN ∪ READ_ONLY）字段成立。对 EDITABLE 字段，省略**就是清空**——那是客户端**唯一**的清除手段（前端 `toCustomFieldPayload` 会跳过空值）。
2. **不承诺**必填 READ_ONLY 字段的省略能被回补：`saveValues` 的必填校验**早于**回补 ⇒ 它会先 422 `CUSTOM_FIELD_REQUIRED`。**登记为债务**，本批**不修**。
3. **不承诺**回补在**其他实体**上的端到端覆盖：修复是实体无关的，但本批只在 **LEAD / CUSTOMER** 路径上做端到端用例。
4. **不承诺**「回传的格式永远安全」：现有回传之所以逐字节相等，**只是因为**其初始值来自库中的原始字符串。**登记为债务**。
5. **不承诺** `create` 路径上的行为：`saveValues` 在 `create` 时库中无原值 ⇒ 回补集合为空 ⇒ **无补偿可做**（这与 056 无关，但读者容易把它读成漏洞）。
